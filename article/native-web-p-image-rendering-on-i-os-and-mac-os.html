Native WebP Image Rendering on iOS and macOS

Apple platforms natively support the WebP image format across several foundational graphics and user interface frameworks. Starting with iOS 14 and macOS 11 (Big Sur), developers can decode, display, and encode WebP images directly without relying on third-party libraries like libwebp. This native capability is powered primarily by low-level image processing APIs and exposed seamlessly through high-level UI components across both operating systems.

ImageIO

ImageIO is the core framework responsible for low-level image decoding and metadata handling in iOS and macOS. It serves as the underlying engine that makes WebP support possible across higher-level frameworks. Using CGImageSourceCreateWithData or CGImageSourceCreateWithURL, developers can read WebP data, inspect properties, extract metadata, and generate a CGImage for rendering. ImageIO also supports encoding images into the WebP format via CGImageDestination.

UIKit and AppKit

For standard application interfaces, the platform-specific UI frameworks handle WebP automatically:

  • UIKit (iOS): UIImage natively parses WebP files through initializers like UIImage(named:), UIImage(contentsOfFile:), and UIImage(data:). An UIImageView can display these images without custom configuration.
  • AppKit (macOS): NSImage provides the equivalent functionality on macOS, allowing WebP files to be initialized directly via NSImage(named:), NSImage(contentsOfFile:), or NSImage(data:) and displayed inside an NSImageView.

SwiftUI

SwiftUI leverages the platform's native image infrastructure. WebP assets included in an Asset Catalog (Xcode 12 and later) can be displayed directly using Image("asset_name"). For dynamically downloaded or generated WebP data, developers can initialize a SwiftUI Image by first bridging through UIImage on iOS or NSImage on macOS.

WebKit

The WebKit framework natively handles WebP content rendered within web views. A WKWebView renders WebP images inside HTML elements (<img>, CSS background images, and <picture> tags) natively without requiring polyfills or JavaScript decoders.

Core Image

Core Image can process WebP data by initializing a CIImage using CIImage(data:) or CIImage(contentsOf:). Because Core Image integrates directly with ImageIO under the hood, developers can apply image filters, transformations, and color adjustments to WebP images natively before rendering them to a context.
