Automatic WebP Asset Negotiation in Apache

Serving WebP images automatically improves website load times without requiring changes to existing HTML markup. This guide details how to configure the Apache HTTP Server to dynamically deliver WebP equivalents of JPEG and PNG files by evaluating the client browser's Accept header using mod_rewrite, mod_headers, and mod_mime.

Required Apache Modules

To support conditional WebP delivery, ensure the following core Apache modules are enabled in your server configuration:

  • mod_rewrite: Evaluates incoming request headers and rewrites the file path to the .webp asset if conditions are met.
  • mod_headers: Appends the Vary: Accept header to prevent reverse proxies and CDNs from serving cached WebP images to incompatible clients.
  • mod_mime: Assigns the correct MIME type (image/webp) to the served content.

Enable these modules via the command line on Debian/Ubuntu systems:

sudo a2enmod rewrite headers mime
sudo systemctl restart apache2

Configuration via .htaccess or VirtualHost

Add the following directives to your primary Apache configuration file (httpd.conf), VirtualHost configuration, or an .htaccess file in the document root:

<IfModule mod_mime.c>
    # Ensure the server recognizes the WebP MIME type
    AddType image/webp .webp
</IfModule>

<IfModule mod_rewrite.c>
    RewriteEngine On

    # 1. Check if the browser explicitly accepts WebP images
    RewriteCond %{HTTP_ACCEPT} image/webp

    # 2. Check if an identical file with a .webp extension exists on the server
    RewriteCond %{DOCUMENT_ROOT}/$1.$2.webp -f [OR]
    RewriteCond %{REQUEST_FILENAME}\.webp -f

    # 3. Rewrite the request to the WebP equivalent
    RewriteRule ^(.+)\.(jpe?g|png)$ $1.$2.webp [T=image/webp,E=accept:1,L]
</IfModule>

<IfModule mod_headers.c>
    # Inform caching servers and CDNs to store separate versions based on Accept headers
    Header append Vary Accept env=REDIRECT_accept
</IfModule>

Configuration Breakdown

  1. RewriteCond %{HTTP_ACCEPT} image/webp: Inspects the client's request headers. If the browser does not declare support for image/webp, the rule is bypassed and the original JPEG or PNG file is delivered.
  2. RewriteCond ... -f: Verifies that a corresponding .webp file physically exists on the disk before redirecting. If no pre-converted file is found (e.g., image.jpg.webp), the server falls back to serving the standard image format.
  3. RewriteRule: Silently swaps the response to the .webp variant without altering the URL in the browser's address bar. The [T=image/webp] flag sets the Content-Type header directly.
  4. Header append Vary Accept: Instructs intermediate caches, proxies, and browser caches to maintain distinct cached copies based on the visitor's Accept header. This prevents an incompatible browser from being served a cached WebP asset meant for a modern browser.
