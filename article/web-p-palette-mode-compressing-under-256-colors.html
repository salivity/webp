WebP Palette Mode: Compressing Under 256 Colors

This article examines how the WebP image format optimizes low-color graphics using its lossless color indexing transform. When an image contains 256 or fewer distinct ARGB colors, WebP replaces raw pixel color values with compact palette indices, packs sub-byte values to maximize data density, and compresses the result using entropy coding. Understanding this workflow explains why WebP achieves significantly smaller file sizes than legacy formats like GIF or 8-bit PNG while preserving full color fidelity and alpha transparency.

The Color Indexing Transform

WebP Lossless achieves its efficiency on low-color imagery through a dedicated preprocessing step known as the Color Indexing Transform. During encoding, the WebP encoder analyzes the entire image to count unique ARGB (Alpha, Red, Green, Blue) values. If the unique color count does not exceed 256, the encoder determines that storing full 32-bit color information for every individual pixel is redundant.

Instead of writing individual red, green, blue, and alpha channels across the canvas, the encoder constructs a color palette. This palette is an ordered array containing only the unique colors present in the original image.

Storing the Palette

The generated palette is stored directly in the WebP bitstream as a one-dimensional sub-image. Each entry in the palette represents a fully qualified 32-bit ARGB color value. Because the palette itself is treated as an image, it is recursively compressed using WebP's standard lossless encoding mechanisms, reducing its footprint down to only the bare essential bytes needed to describe the color list.

Pixel-to-Index Mapping and Channel Packing

Once the palette is established, the encoder replaces every pixel in the source image with an integer index referencing its corresponding position in the palette. WebP maps these indices to the image's green channel, which acts as the primary data container in the lossless pipeline.

To maximize spatial efficiency, WebP employs sub-byte packing based on the total number of colors:

  • 1 to 2 colors: Stored using 1 bit per pixel (up to 8 pixels packed into a single byte).
  • 3 to 4 colors: Stored using 2 bits per pixel (up to 4 pixels packed into a single byte).
  • 5 to 16 colors: Stored using 4 bits per pixel (2 pixels packed into a single byte).
  • 17 to 256 colors: Stored using a standard 8-bit byte per pixel.

By packing multiple pixels into single bytes whenever possible, WebP drastically reduces the raw data volume before any further compression algorithms are applied.

Entropy Coding and Spatial Compression

After the image data has been transformed into a packed stream of palette indices, it passes through the standard WebP lossless entropy stages:

  1. LZ77 Backward References: The encoder scans for repeating patterns of indices (such as solid color fills, gradients, or repeating graphical elements) and replaces them with compact distance-length pairs.
  2. Prefix Coding (Canonical Huffman): The remaining indices and distance-length codes are assigned variable-length prefix codes. Frequently used palette indices receive shorter codes, while rarely used indices receive longer ones.

Because palette indexing strips away channel-to-channel variations and normalizes graphical data into a small, predictable set of integers, the entropy coder can compress the remaining data far more efficiently than it could unindexed color channels. The result is a fully lossless image that retains full 8-bit alpha transparency per color while maintaining a minimal file size.
