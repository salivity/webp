WebP Macroblocks vs JPEG 8x8 DCT Blocks

While both JPEG and lossy WebP compress image data by partitioning images into small pixel grids, their fundamental difference lies in how those blocks are processed: JPEG transforms raw pixel values directly within isolated 8x8 blocks using the Discrete Cosine Transform (DCT), whereas WebP utilizes 16x16 macroblocks powered by spatial intra-prediction borrowed from the VP8 video codec, encoding only the predictive residual error rather than the raw pixel data.

Block Dimensions and Sub-Partitioning

JPEG enforces a rigid grid structure across the image, slicing the color channels into uniform 8x8 pixel blocks. Every 8x8 block is processed as an autonomous unit throughout the compression pipeline.

WebP structures image data into larger 16x16 pixel macroblocks for luma (brightness) and 8x8 blocks for chroma (color). These macroblocks are further divided into 4x4 sub-blocks for transformation. This hierarchical structure allows the encoder to adapt dynamically to local image details rather than applying a fixed grid resolution across the entire canvas.

Intra-Prediction vs. Direct Transformation

The most significant technical departure is WebP's use of intra-frame prediction prior to frequency transformation:

  • JPEG (Direct Transform): JPEG takes the raw spatial values of an 8x8 block, shifts the values, and immediately applies a 2D DCT. It does not reference adjacent blocks to guess pixel trends; each block must independently describe its entire contents from scratch.
  • WebP (Predictive Residuals): WebP predicts the pixel values of a target block by extrapolating from the already decoded boundary pixels of adjacent blocks above and to the left. The encoder selects from several directional prediction modes (such as Horizontal, Vertical, DC, and TrueMotion). It then subtracts this prediction from the actual image data, producing a "residual" (the difference or error). Only this residual error is sent to the transform stage.

Because spatial correlation between adjacent pixels is usually high, the residual contains far less energy than the original pixel data, allowing WebP to discard more information without noticeable visual loss.

Transform Pipeline

Because JPEG and WebP handle block data differently, their mathematical transforms also diverge:

  • JPEG applies an 8x8 DCT directly to the spatial pixel data, generating 64 frequency coefficients (1 DC coefficient representing average brightness and 63 AC coefficients representing high-frequency detail).
  • WebP applies a smaller 4x4 DCT to the prediction residuals. Additionally, the DC coefficients of these 4x4 sub-blocks are gathered into a second-level 4x4 matrix and transformed using a Walsh-Hadamard Transform (WHT) to eliminate any remaining redundancy across the macroblock.

Impact on Compression Artifacts

At low bitrates, JPEG's independent 8x8 DCT approach causes "blocking artifacts," where the hard borders of the individual 8x8 grids become prominently visible because adjacent blocks do not share contextual edge data.

WebP avoids prominent grid lines because intra-prediction maintains directional continuity across block boundaries. Furthermore, WebP integrates an in-loop deblocking filter that automatically smooths edges across macroblocks during decoding, resulting in softer, less jarring degradation compared to standard JPEG compression.
