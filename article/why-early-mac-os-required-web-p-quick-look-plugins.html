Why Early macOS Required WebP QuickLook Plugins

Early versions of macOS lacked native support for Google’s WebP image format, preventing core system utilities like Finder, Preview, and QuickLook from rendering these files out of the box. Because macOS relied on the centralized ImageIO framework for system-wide image decoding—and Apple did not include a WebP decoder in that framework until macOS Big Sur—users had to rely on custom third-party QuickLook plugins bundling open-source decoders to generate file previews.

The Role of the ImageIO Framework

macOS handles image rendering through a system-level framework called ImageIO. When a user selects a file and presses the Spacebar, the QuickLook daemon asks ImageIO to parse and render the image data.

Because ImageIO was designed as a closed, system-managed pipeline, it could only process formats explicitly supported by Apple, such as JPEG, PNG, TIFF, and later HEIC. Without a native decoder for WebP built into ImageIO, macOS treated .webp files as unknown binary data, displaying only a generic document icon rather than an image thumbnail.

Industry Rivalry and Delayed Adoption

Google introduced the WebP format in 2010 to provide smaller, richer images to speed up the web, deriving the compression algorithm from the VP8 video codec. Apple historically hesitated to adopt Google-backed media formats across its operating systems, favoring open ISO standards or its own preferred technologies—such as HEIF/HEIC, which Apple integrated into macOS High Sierra in 2017.

Because Safari and macOS initially avoided WebP, Apple had little incentive to update ImageIO with WebP decoding libraries, leaving the format unsupported at the system level for nearly a decade.

How Third-Party QuickLook Plugins Filled the Gap

To resolve this limitation, open-source developers took advantage of QuickLook’s modular architecture. macOS allowed external generators—bearing the .qlgenerator bundle extension—to register themselves as handlers for specific Uniform Type Identifiers (UTIs) or file extensions.

Developers compiled Google's official decoding library (libwebp) into lightweight plugins, such as WebP.qlgenerator. When placed in /Library/QuickLook or ~/Library/QuickLook, these plugins intercepted WebP files, bypassed the standard ImageIO pipeline, decoded the image data in memory, and handed a rendered bitmap back to QuickLook for instant viewing in Finder.

Native Support in macOS Big Sur

The requirement for custom QuickLook plugins ended in 2020 with the release of macOS 11 Big Sur and iOS 14. Apple officially integrated WebP decoders into ImageIO and added native WebP rendering to Safari. This update allowed Finder, Preview, and QuickLook to parse WebP files automatically without third-party intervention.
