Lossless WebP FourCC in RIFF Containers

WebP image files utilize the Resource Interchange File Format (RIFF) container structure to package compressed image data and associated metadata. Within this container, distinct four-character codes (FourCCs) identify the specific encoding format of the bitstream payload. For lossless WebP images, the FourCC identifier used inside the RIFF chunk header is VP8L. This article details the role of the VP8L identifier, how the RIFF wrapper organizes lossless data, and how decoders read this structure.

The Lossless Identifier: VP8L

The four-character code VP8L signifies an independent, lossless WebP bitstream. When an image parser encounters this FourCC tag within a RIFF chunk, it routes the payload to the WebP lossless decompression pipeline rather than a lossy VP8 video-derived decoder.

In ASCII representation, the identifier corresponds to the following byte values:

  • 'V' = 0x56
  • 'P' = 0x50
  • '8' = 0x38
  • 'L' = 0x4C

RIFF Wrapper Anatomy for Lossless WebP

A standard lossless WebP file consists of a main RIFF header followed by the VP8L data chunk:

  1. RIFF Header: The first 12 bytes of the file contain:

    • Chunk ID: The ASCII characters RIFF (0x52 0x49 0x46 0x46).
    • File Size: A 32-bit little-endian integer representing total file size minus 8 bytes.
    • Format: The ASCII characters WEBP (0x57 0x45 0x42 0x50).

  2. VP8L Chunk:

    • Chunk FourCC: The 4-byte ASCII string VP8L.
    • Chunk Size: A 32-bit little-endian integer indicating the exact payload size in bytes.
    • Chunk Payload: The lossless compressed bitstream, beginning with a mandatory 1-byte signature (0x2F).
    • Padding: If the chunk size is odd, a single 0x00 byte is appended to maintain 2-byte word alignment, though this byte is not included in the chunk size field.

Comparison with Other WebP FourCCs

WebP containers use distinct FourCC values depending on the compression method and features included:

  • VP8 (VP8 with a trailing space): Signifies a lossy bitstream based on the VP8 video compression format.
  • VP8L: Signifies a lossless bitstream using spatial transformations, color cache indexing, and entropy coding.
  • VP8X: Signifies an extended format header. When features like alpha transparency, EXIF metadata, ICC color profiles, or animations are combined with a lossless image, the file begins with a VP8X chunk, and the VP8L bitstream appears as a sub-chunk within the container.

Parsing the VP8L Stream

Once the VP8L chunk header is read, the decoder inspects the first byte of the payload. Every valid WebP lossless stream starts with the signature byte 0x2F. The subsequent bits define the image width, image height, alpha presence flag, and version number before the compressed image transformations and entropy-coded data begin.
