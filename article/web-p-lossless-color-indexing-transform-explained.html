WebP Lossless Color Indexing Transform Explained

The color indexing transform is a crucial preprocessing step in WebP lossless compression designed to drastically reduce file sizes for images containing a limited set of unique colors. By identifying images with small color palettes—such as icons, charts, and flat graphics—the WebP encoder replaces heavy 32-bit ARGB pixel representations with lightweight index references to a compact palette. This article breaks down how the color indexing transform works, how it reduces data entropy, and why it is essential to the performance of lossless WebP files.

The Role of Color Indexing in WebP Lossless

During lossless compression, WebP utilizes four distinct image transforms to remove data redundancy before final entropy encoding:

  1. Predictor transform
  2. Cross-color transform
  3. Subtract green transform
  4. Color indexing transform

The color indexing transform specifically targets palette-based imagery. Instead of treating every pixel as a continuous combination of Alpha, Red, Green, and Blue channels, the encoder checks whether the entire image contains 256 or fewer unique ARGB values. If it does, using a color index table provides a much more compact representation than storing full color channels.

How the Transform Works

The transform operates through a structured process during the encoding stage:

  1. Palette Creation: The encoder scans the image to count all unique ARGB values. If the count is 256 or fewer, the encoder compiles these colors into an indexed array called the color palette.
  2. Pixel Substitution: The original 32-bit ARGB values at each pixel coordinate are substituted with the corresponding index from the palette (e.g., color 0xFFFFFFFF becomes index 0, color 0x00000000 becomes index 1).
  3. Channel Mapping: In the WebP bitstream, the palette index is stored directly in the green channel of the pixel data, while the other channels are zeroed or omitted.
  4. Sub-Byte Packing: To maximize efficiency, WebP dynamically packs multiple indices into a single byte depending on the total palette size:
    • 1–2 colors: Stored using 1 bit per pixel (8 pixels per byte).
    • 3–4 colors: Stored using 2 bits per pixel (4 pixels per byte).
    • 5–16 colors: Stored using 4 bits per pixel (2 pixels per byte).
    • 17–256 colors: Stored using 8 bits per pixel (1 pixel per byte).

Impact on Downstream Compression

By converting full ARGB values into small integer indices, the color indexing transform drastically simplifies the data stream:

  • Lower Alphabet Size: The subsequent entropy coder handles a symbol alphabet of at most 256 symbols instead of dealing with the full combinations of four separate 8-bit channels.
  • Higher Redundancy for LZ77: Repeated visual patterns map to identical, short byte sequences, enabling the LZ77 backwards-referencing engine to find longer and more frequent matches.
  • Reduced Entropy: The overall entropy of the image data drops significantly, allowing the canonical Huffman coding stage to assign very short prefix codes to frequent colors.

Decoding the Transformed Image

When decoding a lossless WebP file, the process is inverted. The decoder first parses the embedded palette from the header data. As it decodes the pixel stream, it reads the packed bit values from the green channel and maps each index back to the full 32-bit ARGB color defined in the palette, completely reconstructing the original image without any loss of quality.
