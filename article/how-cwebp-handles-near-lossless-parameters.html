How cwebp Handles Near-Lossless Parameters

The cwebp command-line utility provides the -near_lossless parameter to balance the superior compression ratios of lossy encoding with the pixel precision of lossless formats. This article covers how cwebp interprets this parameter, the underlying spatial preprocessing algorithms applied to image data, the numerical range of the setting, and how it interacts with other encoding flags to optimize image file sizes.

The -near_lossless feature is an extension of WebP’s lossless encoding engine (VP8L). Rather than discarding high-frequency information through transform coding as traditional lossy compression does, near-lossless mode subtly adjusts the RGB values of pixels before feeding them into the standard lossless compression pipeline. The goal is to modify pixel values just enough to maximize pattern repetition and spatial predictability without introducing visible artifacts.

The parameter accepts an integer value ranging from 0 to 100:

  • 100: Disables all preprocessing. The image is compressed using standard, bit-exact WebP lossless compression.
  • 0: Applies the maximum degree of pixel alteration, resulting in the smallest file size at the cost of noticeable image smoothing or color shifts.
  • Values between 1 and 99: Gradually scale the allowable difference between the original pixel values and the preprocessed values. Practical implementations typically use values between 60 and 80 to achieve significant file size reductions while retaining near-perfect visual fidelity.

At the algorithmic level, cwebp analyzes spatial predictors—such as left, top, and cross-color predictors—across neighboring pixels. If a slight shift in a pixel's value allows it to match a predicted value or repeat an existing pattern, cwebp alters that pixel, provided the change remains within a threshold determined by the parameter setting. This preprocessing dramatically increases the efficiency of the subsequent LZ77 dictionary matching and entropy coding (Huffman or canonical) stages of VP8L.

When using -near_lossless, the standard quality parameter -q changes its typical role. Instead of controlling visual lossiness, -q dictates the algorithmic effort and CPU time spent searching for optimal predictions and dictionary matches. The visual distortion is governed strictly by the value passed to -near_lossless. Consequently, command syntax such as cwebp -near_lossless 70 -q 100 input.png -o output.webp produces maximum compression efficiency at a moderate level of preprocessing.
