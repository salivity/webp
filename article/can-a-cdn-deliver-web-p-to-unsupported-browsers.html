Can a CDN Deliver WebP to Unsupported Browsers?

A misconfigured Content Delivery Network (CDN) can deliver WebP images to browsers that cannot decode them, often resulting in broken image icons or failed page renders for users. This issue occurs when an edge server caches a WebP image generated for a modern browser and subsequently serves that identical cached file to an older browser that lacks WebP support. Understanding how content negotiation fails at the CDN level is essential to preventing degraded user experiences across legacy devices and embedded web views.

How Content Negotiation Works

Modern browsers communicate image format support to web servers using the HTTP Accept request header. A browser supporting WebP sends a header like:

Accept: image/webp,image/apng,image/*,*/*;q=0.8

When a browser lacks WebP support, the image/webp token is absent. In an optimal setup, the origin server or the CDN detects this header and serves a compatible format, such as JPEG or PNG, rather than WebP.

The Primary Cause: Missing or Ignored Vary Headers

The most frequent reason a CDN serves incompatible WebP images is the improper handling of the Vary header.

When an edge server caches an asset, it typically uses the URL path as the primary cache key. If modern browser "User A" requests /image.jpg, the CDN or origin converts and serves it as a WebP image. If the response does not include Vary: Accept, the CDN treats the WebP payload as the universal response for /image.jpg.

When legacy browser "User B" requests /image.jpg, the CDN fulfills the request directly from its cache. Because the cache key was solely based on the URL, the legacy browser receives a WebP payload with an incompatible format, causing the image to break.

Misconfigured Edge Transformations

Many modern CDNs offer automated image optimization tools. These tools convert images on the fly at the edge. A misconfiguration occurs when:

  • Header Stripping: The CDN strips the Accept header before forwarding requests to the origin, preventing the origin from determining browser capabilities.
  • Forced Format Overrides: Edge rules or workers are configured to convert all incoming image requests to WebP unconditionally, without evaluating client request headers.
  • Improper Cache Key Customization: The CDN is set to ignore query parameters or headers during edge caching, collapsing formats into a single cache bucket.

How to Fix CDN WebP Delivery

To resolve this issue, administrators must ensure that cached image variants are segregated based on browser support:

  1. Implement Vary: Accept: Configure the origin server to return the Vary: Accept HTTP response header for all dynamically negotiated images. This instructs the CDN to maintain separate cache entries for clients that accept WebP versus those that do not.
  2. Normalize the Accept Header: Because Accept headers vary widely between browsers, varying cache keys by the raw header can significantly reduce cache hit rates. Use CDN edge logic to normalize the incoming header into a simple boolean flag (such as supports-webp: true) and include that flag in the CDN cache key.
  3. Use the HTML <picture> Element: Rather than relying purely on server-side content negotiation, use the <picture> element with <source type="image/webp"> alongside fallback <img> tags pointing to standard JPEG or PNG files. This delegates format selection to the browser client itself.
