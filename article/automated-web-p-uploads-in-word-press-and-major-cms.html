Automated WebP Uploads in WordPress and Major CMS

This article examines how leading content management systems—primarily WordPress, Shopify, Drupal, and Joomla—handle the automated processing, conversion, and serving of WebP media uploads. It explores native core functionality, content delivery network (CDN) integrations, server-level requirements, and the automated workflows used to optimize web performance while maintaining backwards compatibility.

How WordPress Manages WebP Media

WordPress natively supports uploading and viewing WebP images since version 5.8. However, core WordPress does not automatically convert standard JPEG or PNG uploads into WebP files out of the box.

To achieve automated conversion upon upload, WordPress relies on the following mechanisms:

  • Official Performance Lab Plugin: Developed by the WordPress Core Performance Team, this modular plugin allows sites to automatically generate WebP versions of uploaded JPEG images and serve them when supported.
  • Third-Party Optimization Plugins: Solutions such as Smush, Imagify, ShortPixel, and LiteSpeed Cache hook into the media upload pipeline (wp_handle_upload). When an image is uploaded, these plugins intercept the file, generate a compressed WebP copy alongside the original, and create rewrite rules or <picture> elements for front-end delivery.
  • Server Library Dependencies: For automated generation to function, the underlying host server must support either the GD Graphics Library compiled with WebP support or the ImageMagick (imagick) PHP extension.

Automated WebP Handling in Shopify

Shopify approaches media optimization at the platform and infrastructure level rather than the application level.

  • Automatic Edge Conversion: When merchants upload images in formats like JPEG, PNG, or GIF, Shopify stores the original asset and dynamically converts it to WebP or AVIF at the CDN edge.
  • Content Negotiation: Shopify detects the client browser’s Accept HTTP header. If the browser supports WebP, Shopify automatically serves the WebP derivative without requiring store owners to configure settings, install third-party apps, or alter HTML templates.

Drupal and WebP Workflows

Drupal provides flexible, configurable media handling natively and through its module ecosystem.

  • Drupal Core Image Styles: Starting with Drupal 9.2, core supports WebP format generation within its native Image Styles system. Administrators can configure custom image presets (e.g., thumbnail, medium, large) to output files directly in WebP format.
  • Derivative Generation: When an image is requested, Drupal generates the WebP derivative on demand using PHP’s GD or ImageMagick toolkits and caches the result for subsequent requests.
  • Fallback Modules: Modules like the WebP module provide automated fallback mechanisms, serving the WebP variant to compatible browsers while retaining the original JPEG/PNG for older user agents.

Joomla and WebP Integration

Joomla introduced native WebP support in Joomla 4, allowing the Media Manager to recognize, preview, and accept WebP files.

  • Native Management: While Joomla 4 and 5 allow users to upload and manage WebP files directly, core automated conversion of existing JPEGs/PNGs is limited.
  • System Plugins: Automated on-upload conversion in Joomla is typically handled by system plugins or optimization extensions (such as JCH Optimize). These tools intercept uploaded media, generate WebP alternatives, and modify the rendered page source to deliver responsive <picture> tags.

Core Mechanisms of CMS WebP Automation

Across all major platforms, automated WebP handling generally falls into two distinct architectures:

  1. Pipeline Execution (Storage-Heavy): The CMS creates physical .webp duplicates of an image and its various display sizes upon upload. This increases local disk usage but minimizes real-time server processing during page visits.
  2. On-the-Fly / Edge Transformation (Compute-Heavy): The CMS or CDN stores only the source image and dynamically converts, compresses, and caches the WebP variant at the network edge. This eliminates duplicate local storage and ensures immediate format updates across the entire site.
