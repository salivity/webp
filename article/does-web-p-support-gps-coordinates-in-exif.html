Does WebP Support GPS Coordinates in EXIF?

Yes, the WebP image format fully supports embedded geospatial metadata, including GPS coordinates, stored within standard EXIF tags. While commonly associated with lightweight web delivery, WebP relies on an extensible container structure capable of carrying the same EXIF and XMP metadata payloads found in traditional formats like JPEG and TIFF. This article explains how WebP encapsulates geospatial data, the container mechanics involved, and the practical factors that dictate whether GPS data is preserved or stripped.

How WebP Stores EXIF Metadata

WebP uses the Resource Interchange File Format (RIFF) container. When an image contains metadata or advanced features (such as transparency or animation), it uses the Extended WebP file format, identified by a VP8X header chunk.

Within this extended container, dedicated chunks store non-image data:

  • EXIF Chunk: Stores standard Exchangeable Image File Format data, including camera settings, timestamps, and GPS metadata.
  • XMP Chunk: Stores Extensible Metadata Platform data, which can also carry duplicate or specialized geospatial namespaces.

Because the data inside the EXIF chunk uses standard EXIF formatting, geospatial tags—such as GPSLatitude, GPSLongitude, GPSAltitude, and GPSTimestamp—are structured identically to how they appear in a JPEG.

Reading and Writing GPS Data in WebP

Modern image processing tools and libraries treat WebP metadata identically to metadata in legacy formats. You can inspect and modify GPS tags in WebP files using tools such as:

  • ExifTool: Reads and writes EXIF:GPSLatitude, EXIF:GPSLongitude, and related tags natively within WebP containers.
  • ImageMagick: Retains or writes metadata profiles during conversion to and from WebP.
  • libwebp (cwebp / dwebp): Google's official WebP encoder supports the -metadata flag (e.g., -metadata exif or -metadata all), allowing developers to preserve embedded GPS information when converting source images.

Practical Considerations: Web Delivery vs. Storage

While the format supports GPS data natively, geospatial information is often absent in WebP files encountered on the web due to two main factors:

  1. File Size Optimization: WebP is predominantly used to improve page load speeds. Most automated build pipelines, content delivery networks (CDNs), and image optimization plugins automatically strip EXIF chunks (including GPS tags) by default to shave kilobytes off the file size.
  2. Privacy Protection: Many web platforms actively purge GPS coordinates during the conversion to WebP to prevent the accidental leakage of a user's physical location.

If you require geospatial metadata to remain intact within WebP images—such as for digital asset management, mapping applications, or archival workflows—you must explicitly configure your encoding tools to preserve the EXIF chunk.
