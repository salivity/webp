How to Serve WebP Images with HTML Picture Fallbacks

Modern web performance relies on next-generation image formats like WebP to reduce payload sizes without sacrificing visual quality, but not all legacy environments fully support them. This guide explains how to use the HTML <picture> element to serve lightweight WebP images to compatible modern browsers while automatically providing robust JPEG or PNG fallbacks for unsupported browsers.

The Mechanics of the <picture> Element

The HTML <picture> element is a wrapper that contains one or more <source> tags followed by a single mandatory <img> tag. Unlike standard image tags that offer a single source file, the <picture> element allows developers to define multiple candidate resources. The browser evaluates these candidates sequentially from top to bottom and loads the first resource it natively supports.

Basic Syntax for Format Switching

To serve WebP with a fallback, specify the WebP asset inside a <source> element and define its MIME type using the type attribute. Place the fallback format (such as JPEG or PNG) inside the nested <img> tag:

<picture>
  <source srcset="image.webp" type="image/webp">
  <img src="image.jpg" alt="A descriptive description of the image" width="800" height="600" loading="lazy">
</picture>

How the Browser Handles the Fallback

When a browser encounters this markup, it performs the following steps:

  1. Format Evaluation: The browser checks the type="image/webp" attribute on the <source> tag. If the browser supports WebP decoding, it selects image.webp and ignores any subsequent sources.
  2. Fallback Execution: If the browser does not recognize or support the image/webp MIME type, it skips that <source> tag and advances to the next element.
  3. Rendering: The browser reaches the <img> tag and loads image.jpg.

The nested <img> element is mandatory. While the <source> tags supply alternative sources, the <img> tag provides the actual rendering box, handles accessibility through the alt attribute, and dictates layout dimensions via width and height attributes.

Combining WebP with Responsive Resolutions

The <picture> element can simultaneously handle format switching and responsive sizing across different screen densities and viewport widths by utilizing the srcset and sizes attributes:

<picture>
  <!-- WebP sources for different display resolutions -->
  <source 
    type="image/webp" 
    srcset="image-small.webp 400w, image-large.webp 800w" 
    sizes="(max-width: 600px) 400px, 800px">

  <!-- Fallback JPEG sources -->
  <source 
    type="image/jpeg" 
    srcset="image-small.jpg 400w, image-large.jpg 800w" 
    sizes="(max-width: 600px) 400px, 800px">

  <!-- Universal fallback -->
  <img src="image-large.jpg" alt="A descriptive description of the image" width="800" height="600" loading="lazy">
</picture>

Key Implementation Best Practices

  • Order Matters: Always place cutting-edge formats (like AVIF or WebP) in <source> tags above older formats. Browsers select the first compatible option they parse.
  • Keep Dimensions on the <img> Tag: Apply width, height, and CSS styling directly to the <img> element. Do not apply dimension attributes to <source> tags. This reserves space before the image loads and prevents Cumulative Layout Shift (CLS).
  • Accurate MIME Types: Always declare the type attribute accurately (e.g., type="image/webp"). Without the type attribute, the browser must download the file header to determine support, nullifying performance benefits.
