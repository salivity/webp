Can You Use WebP Images in Open Graph Tags?

While the official Open Graph protocol technically supports modern formats like WebP, real-world support across major social media platforms and messaging apps remains inconsistent. This article covers how the Open Graph protocol defines WebP usage, how major networks like Facebook, X (formerly Twitter), and LinkedIn handle the format, and the recommended best practices to ensure your social link previews always display reliably.

The Open Graph Protocol Specification

The Open Graph protocol allows website owners to define preview metadata using standard <meta> tags. By specification, the protocol does not restrict images to legacy formats like JPEG, GIF, or PNG. You can define a WebP image and declare its MIME type using the following markup:

<meta property="og:image" content="https://example.com/preview.webp" />
<meta property="og:image:type" content="image/webp" />
<meta property="og:image:width" content="1200" />
<meta property="og:image:height" content="630" />

Declaring og:image:type explicitly informs scrapers of the format before they download the asset. However, a platform's scraper must still be programmed to parse, process, and render that format.

Platform Support Breakdown

Support for WebP in social link previews varies significantly depending on the platform scraping your URL:

  • X (Twitter): X supports WebP images in its card parser. Both summary and summary_large_image cards will generally render WebP files without issue, provided the file size remains within the platform's limits (under 5MB).
  • Facebook: Meta's crawler has historically had inconsistent support for WebP. While Facebook can display WebP files inside its feed, the Open Graph crawler sometimes fails to generate thumbnails from .webp URLs, resulting in blank preview boxes.
  • LinkedIn: LinkedIn has strict and conservative preview requirements. It officially recommends PNG and JPEG formats. WebP images frequently fail to render on LinkedIn posts, defaulting to a generic link card with no thumbnail.
  • Discord, Slack, and Telegram: Modern chat applications generally rely on modern rendering engines and handle WebP Open Graph images smoothly.

Why JPG and PNG Remain the Best Choice

Social share images are only fetched when a link is crawled or shared, meaning the bandwidth savings of WebP do not offer the same performance benefits as they do for standard on-page web assets. Because platforms cache the scraped images on their own content delivery networks (CDNs), the end user rarely downloads the file directly from your origin server.

Using WebP for Open Graph images introduces the risk of broken link previews on platforms like LinkedIn or older web crawlers for minimal performance gain.

Best Practice Recommendation

To guarantee 100% visibility across every platform:

  1. Use JPEG or PNG for og:image: Keep your primary Open Graph images formatted as standard JPEG or PNG files, ideally sized at 1200 x 630 pixels and kept under 8MB.
  2. Serve WebP on the Page: Continue using WebP or AVIF for the visible images on your actual web pages to improve Core Web Vitals and load times.
  3. Validate Your URLs: Always run your URLs through developer tools like the Facebook Sharing Debugger, Twitter Card Validator, and LinkedIn Post Inspector to confirm how each crawler interprets your image tags before publishing.
