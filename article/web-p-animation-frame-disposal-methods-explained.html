WebP Animation Frame Disposal Methods Explained

WebP animation relies on frame disposal methods to dictate how individual frames are cleared from the canvas before the next frame renders. Unlike the older GIF specification, which defined four separate disposal modes, the WebP container specification simplifies this process into two distinct disposal behaviors encoded in the animation frame (ANMF) chunk: Do Not Dispose and Dispose to Background. Understanding how these two methods function is essential for optimizing file sizes, preventing rendering artifacts, and ensuring efficient canvas management in animated WebP assets.

The Role of Disposal in the WebP Specification

In an animated WebP file, each frame is stored within an ANMF (Animation Frame) chunk. This chunk defines the frame’s coordinates (frame_x, frame_y), dimensions (frame_width, frame_height), duration, and a 1-byte flags field.

Bit 1 of this flags byte is reserved specifically for the Disposal Method. It informs the rendering engine whether to preserve the current frame's pixels or clear the frame's bounding area before drawing the subsequent frame.

1. Do Not Dispose (Value: 0)

When the disposal bit is set to 0, the decoder preserves the content of the current frame on the canvas.

  • How it works: The renderer draws the frame at its specified offset. When advancing to the next frame, the previous frame’s pixels remain in place, allowing the next frame to draw directly over them.
  • Primary use case: This method is primarily used for delta encoding and incremental updates. If an animation has a static background with small moving parts, only the changing regions need to be encoded in subsequent frames. By not disposing of the previous frames, file sizes are kept small because the static areas are rendered once and never redrawn.

2. Dispose to Background Color (Value: 1)

When the disposal bit is set to 1, the decoder clears the area occupied by the current frame before rendering the next frame.

  • How it works: After the frame’s display duration expires, the bounding box defined by the frame's offset and dimensions (frame_x, frame_y, frame_width, frame_height) is filled with the canvas background color. The background color is defined in the file’s global ANIM chunk (which defaults to fully transparent black #00000000 if not explicitly specified).
  • Primary use case: This method is ideal for isolated moving objects that leave empty space behind them, or when switching between entirely distinct scenes where preserving prior pixel data would produce unwanted visual ghosting.

Interaction with Blending Methods

Disposal methods work directly alongside WebP's Blending Method (controlled by Bit 0 of the ANMF flags).

  • Alpha Blending (0): The new frame's pixels are blended over the existing canvas pixels using alpha composition.
  • No Blending / Overwrite (1): The new frame's pixels overwrite both the color and alpha values of the canvas within the bounding box.

By combining the two disposal behaviors with the two blending options, developers and encoders achieve full control over how canvas memory is cleared and redrawn across complex animation sequences without the overhead of GIF’s legacy "restore to previous" method.
