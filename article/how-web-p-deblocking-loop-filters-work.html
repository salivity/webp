How WebP Deblocking Loop Filters Work

WebP relies on an in-loop deblocking filter to eliminate the grid-like seams and sharp edges, known as block artifacts, that result from lossy compression. By operating directly inside the decoding and encoding loops, this filter evaluates pixel gradients across block boundaries and selectively blends adjacent pixels without softening genuine image details. This article breaks down why these artifacts occur, how WebP determines filtering strength, and the step-by-step process used to smooth block boundaries.

Why Block Artifacts Occur

Lossy WebP encodes images by splitting the canvas into \(16 \times 16\) pixel macroblocks, which are further divided into \(4 \times 4\) sub-blocks for transform coding. Each block undergoes a Discrete Cosine Transform (DCT) or Walsh-Hadamard Transform (WHT), followed by quantization.

Quantization discards high-frequency data to reduce file size. Because adjacent blocks are transformed and quantized independently, the pixel values reconstructed at the boundaries often fail to match seamlessly. At higher compression ratios, these mathematical discrepancies manifest as sharp, visible grids across the image.

The Role of the "In-Loop" Design

WebP inherits its core lossy compression architecture from the VP8 video codec, which utilizes an in-loop filter rather than an external post-processing filter.

Being "in-loop" means the filter runs during the decoding reconstruction phase. When spatial prediction (intra-prediction) predicts future macroblocks, it references the already deblocked pixels rather than the raw, unpolished transform outputs. Because both the encoder and decoder run the identical filtering algorithm at the exact same step, prediction drift is eliminated, leading to better compression efficiency and consistent visual output.

Boundary Detection and Filtering Levels

The deblocking loop filter processes boundaries between \(4 \times 4\) sub-blocks across both luma (brightness) and chroma (color) planes. It executes in two passes: first smoothing vertical edges by filtering horizontally, then smoothing horizontal edges by filtering vertically.

To avoid blurring real subject edges—such as hair, text, or sharp object outlines—the filter relies on dynamic thresholds:

  1. Filter Level: Governed by the quantization parameter (\(Q\)). Higher compression settings trigger a higher base filter level, applying stronger smoothing to combat harsher blockiness.
  2. Edge Thresholds: The algorithm samples pixels immediately flanking a boundary line (\(p_1, p_0 \,|\, q_0, q_1\), where the pipe represents the block boundary). It measures the absolute differences:
    • Across the boundary: \(|p_0 - q_0|\)
    • On the left/top side: \(|p_1 - p_0|\)
    • On the right/bottom side: \(|q_1 - q_0|\)

If the pixel variance across the boundary exceeds predefined limits, WebP classifies the discontinuity as a legitimate photographic edge rather than a compression artifact and skips filtering entirely.

Simple vs. Normal Filtering Modes

Depending on quality profiles and performance constraints, WebP uses two distinct filter implementations:

  • Simple Filter: Optimized for speed, the simple filter operates strictly on luma channels and only adjusts the two boundary pixels (\(p_0\) and \(q_0\)). It computes a signed correction delta, clamps it to a narrow range based on the quantization level, and adds or subtracts this delta to flatten the step between the blocks.
  • Normal (Complex) Filter: Evaluates a wider span of pixels (\(p_3, p_2, p_1, p_0 \,|\, q_0, q_1, q_2, q_3\)). It can smooth up to two or three pixels deep on each side of the edge if the surrounding texture is relatively flat. It checks whether the region qualifies as a "flat area"; if so, it distributes a wider smoothing gradient across multiple pixels to eliminate low-frequency banding.

Pixel Modification Process

Once a boundary qualifies for filtering, WebP calculates a bounded correction value (\(\Delta\)):

\[\Delta = \text{Clamp}(p_0 - q_0 + \text{rounding offsets})\]

The filter updates the inner boundary pixels:

  • \(p_0' = \text{ClampToByte}(p_0 - \Delta)\)
  • \(q_0' = \text{ClampToByte}(q_0 + \Delta)\)

If the normal filter determines that the outer pixels (\(p_1, q_1\)) also require smoothing, smaller, secondary adjustment deltas are derived from \(\Delta\) and applied further outward.

By dynamically calibrating corrections based on local variance and quantization metrics, WebP effectively suppresses artificial gridlines while retaining critical structural sharpness.
