WebP Four-Character Code for Lossy Images

WebP image files use the Resource Interchange File Format (RIFF) container to package compressed visual data into modular chunks labeled with four-character identifiers known as FourCC codes. For lossy WebP image streams, the container uses the specific four-character code VP8 (the letters "VP8" followed by an ASCII space). This article explains how this identifier functions within the WebP container architecture and how decoders parse lossy image streams.

The VP8 FourCC Identifier

The four-character code that signifies a lossy WebP image stream is VP8 (hexadecimal: 0x56 0x50 0x38 0x20). The trailing space is mandatory because the RIFF container specification requires all chunk tags to consist of exactly four ASCII bytes.

When an application saves an image using lossy WebP compression, the underlying bitstream uses the VP8 video codec's intra-frame compression algorithm. The container assigns the VP8 FourCC tag to the primary data chunk holding this encoded payload.

Container Structure for Lossy WebP

A basic lossy WebP file consists of a simple RIFF header followed by a single VP8 data chunk:

  1. RIFF Header: The first four bytes contain the ASCII letters RIFF.
  2. File Size: A 4-byte little-endian integer indicating total file size minus eight bytes.
  3. WebP Signature: The four bytes WEBP identify the specific RIFF payload.
  4. Chunk Identifier: The four bytes VP8 designate that a lossy bitstream follows.
  5. Chunk Size: A 4-byte little-endian integer indicating the size of the raw VP8 data stream.
  6. VP8 Payload: The lossy bitstream, padded with a single null byte if the payload length is odd.

Comparison with Other WebP Chunk Types

WebP uses different FourCC codes to identify other compression modes and features:

  • VP8 : Lossy image stream based on VP8 keyframe encoding.
  • VP8L: Lossless image stream using WebP's native lossless algorithm.
  • VP8X: Extended file header describing advanced features such as ICC color profiles, EXIF metadata, transparency (alpha channels), or animation.

When a lossy image contains an alpha channel for transparency or includes metadata, an extended VP8X chunk appears first, followed later by an ALPH chunk (for transparency) and the VP8 chunk (for color data).

How Decoders Read the Stream

When an image viewer or browser encounters a WebP file, it reads the initial header to verify the RIFF and WEBP markers. It then reads the FourCC tag of the subsequent chunk. Seeing VP8 , the parser routes the contained payload directly to a VP8 keyframe decoder. The decoder extracts the image dimensions, reconstructs macroblocks, and renders the lossy frame without needing to parse alternate compression pipelines like VP8L.
