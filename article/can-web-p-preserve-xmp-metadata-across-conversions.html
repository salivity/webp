Can WebP Preserve XMP Metadata Across Conversions?

WebP fully supports XMP copyright and licensing metadata, but preserving this data across file conversions depends entirely on the tools and settings you use. By default, most image converters, content management systems, and optimization pipelines strip all metadata to minimize file sizes for faster web performance. To retain crucial legal and authorship details when converting images to or from WebP, you must explicitly configure your encoding tools to pass the XMP data payload through to the final file.

How WebP Handles XMP Metadata

The WebP file format uses the Resource Interchange File Format (RIFF) container structure. This container architecture includes dedicated chunks for metadata:

  • EXIF: Stores camera settings, timestamps, and device details.
  • XMP : Stores Extensible Metadata Platform data, including Dublin Core, copyright statuses, creator credits, and digital licensing rights (such as Creative Commons or PLUS tags).
  • ICCP: Holds color profile information.

Because the WebP specification natively reserves a standard chunk specifically for XMP, the format itself introduces no limitations regarding copyright or licensing data integrity.

Why XMP Is Frequently Lost During Conversion

Although the WebP container natively supports XMP, metadata loss usually happens at the software layer during encoding. Common causes include:

  • Aggressive Web Optimization: Conversion utilities often treat metadata as unnecessary overhead. Stripping XMP tags can shave off several kilobytes, which aligns with web performance goals but violates copyright preservation needs.
  • Browser and Canvas Limitations: Converting images client-side using the HTML5 <canvas> API automatically strips all metadata, exporting only raw pixel data.
  • Default Application Profiles: Many image editors separate "Export for Web" workflows from standard file savings, with export workflows defaulting to metadata removal.

How to Preserve XMP Metadata Across Common Tools

To ensure copyright and licensing information persists after conversion, you must use tools that offer explicit metadata retention flags.

1. Google's Official cwebp Encoder

When using Google's native command-line tool, metadata is stripped by default. You must use the -metadata flag to retain it:

# Preserve only XMP metadata
cwebp -q 80 input.jpg -metadata xmp -o output.webp

# Preserve all metadata (EXIF, XMP, and ICC)
cwebp -q 80 input.jpg -metadata all -o output.webp

2. ImageMagick

ImageMagick typically preserves metadata by default unless the -strip command is invoked. However, explicitly handling profiles ensures consistency:

magick input.jpg -quality 80 output.webp

Note: Avoid adding -strip to your command, as this completely purges XMP and EXIF chunks.

3. Adobe Photoshop

  • Save a Copy: Using File > Save a Copy to WebP preserves embedded XMP copyright information.
  • Export As: Using File > Export > Export As will strip metadata unless you change the "Metadata" dropdown menu from "None" to "Copyright and Contact Info".

4. FFmpeg

When using FFmpeg for batch processing, map the metadata streams explicitly to prevent stripping:

ffmpeg -i input.png -c:v libwebp -map_metadata 0 output.webp

How to Verify Preserved Metadata

After conversion, you can verify that the XMP copyright and licensing entries survived by using ExifTool:

exiftool -XMP:All output.webp

If the XMP data was successfully preserved, this command will output all embedded copyright notices, usage terms, and creator attributes. If the output is empty, the conversion pipeline stripped the data, requiring you to adjust the encoder's retention flags.
