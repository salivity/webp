Libwebp Memory Bounds Checking in Decompression

The libwebp library employs a multi-layered approach to memory bounds checking during bitstream decompression to prevent buffer overflows, out-of-bounds reads, and integer wrapping. When decoding WebP images—which rely on either the VP8 lossy codec, the VP8L lossless codec, or RIFF container structures—the library constantly cross-references input bitstream cursors against payload limits and verifies decoded pixel coordinates against strictly pre-allocated canvas memory. Through proactive header validation, safe integer math, and granular cursor management in its bit-reading engines, libwebp ensures memory integrity at every phase of decompression.

Header Validation and Allocation Bounds

Bounds management begins before any compressed pixel data is processed. During the parsing of RIFF containers and VP8/VP8L headers, libwebp reads the canvas dimensions (width and height) and runs validation checks:

  • Dimension Limits: The library verifies that dimensions do not exceed the architectural limits (16,383 × 16,383 pixels for lossy VP8; 65,536 × 65,536 pixels for lossless VP8L).
  • Safe Allocation Math: Calculating the memory required for the decoded output buffer involves multiplying width * height * bytes_per_pixel. To prevent 32-bit integer overflows, libwebp performs these calculations using 64-bit unsigned integers (uint64_t) and helper functions like CheckSizeOverflow(). If the calculated size overflows or exceeds platform-defined limits, the allocation is rejected immediately.
  • Buffer Descriptors: External or internal memory is mapped to a WebPDecBuffer structure, which tracks the buffer's start pointer, total size, stride (pitch), and row capacities.

Bitstream Cursor Tracking via Bit Readers

During decompression, the parser must read variable-length bit sequences without overrunning the compressed input array. libwebp splits this work between two main reader implementations:

1. VP8 Bit Reader (Lossy Decoding)

The VP8BitReader manages the arithmetic boolean entropy decoder used in lossy VP8. It maintains two primary pointers:

  • buf_: The current read pointer in the input data.
  • buf_end_: The boundary marker pointing to the end of the input buffer.

Before fetching subsequent bytes into the internal bit reservoir (the value_ register), the bit reader checks whether buf_ >= buf_end_. If an attempt is made to advance past buf_end_, the reader enters an "exhausted" state, substituting zero bits or setting an internal status flag (status_) to indicate EOF. Macroblock parsers verify this state to prevent infinite loops or undefined memory reads.

2. VP8L Bit Reader (Lossless Decoding)

The VP8LBitReader processes prefix-coded, byte-aligned data. It reads multi-bit patterns using a 32-bit or 64-bit accumulator. Bound checking is enforced by checking if the cursor exceeds len (the size of the input). A dedicated padding safety margin (typically 8 bytes of zero-padding) is often expected or simulated at the end of the bitstream, ensuring that broad bit-reservoir loads do not read invalid memory pages when fetching the final bits of a stream.

Entropy Table and Tree Validation

A critical part of bitstream decompression is constructing dynamic Huffman lookup tables for lossless (VP8L) streams. To guarantee bounded memory writes during this construction:

  • Prefix Code Validation: Dynamic tree codes are checked to confirm that the sum of the code lengths generates a mathematically valid, fully populated prefix tree without over-subscribing the table capacity.
  • Bounded Table Allocation: The tables are allocated based on fixed, mathematically defined limits for the maximum alphabet size (color, entropy, and distance codes). Any bitstream attempting to insert duplicate or excessive symbols into the lookup tables triggers an error code (VP8_STATUS_BITSTREAM_ERROR), terminating decoding before memory corruption can occur.

Output Buffer and Macroblock Clamping

During the synthesis stage, decoded residuals and predictive patterns are written into the output raster:

  • Row and Stride Clamping: Writing into the destination memory is constrained by row-based strides. Decoded macroblocks (16×16 pixels) or sub-blocks (4×4 pixels) along the right and bottom edges of an image may extend past the logical canvas size. The decompression pipeline clips these edge blocks so that memory writes stop exactly at the valid width and height boundaries, avoiding out-of-bounds writes into neighboring heap memory.
  • Rescaler Safety: If scaling or post-processing filters (such as YUV-to-RGB conversion or alpha blending) are active, intermediate scanline buffers are used. The library computes intermediate buffer bounds using fixed-point arithmetic, enforcing that write indices never exceed the allocated row widths.

Through strict separation of input cursor validation, arithmetic overflow checks on dimensions, and boundary clamping on destination buffers, libwebp isolates bitstream anomalies and halts decompression before out-of-bounds reads or writes take place.
