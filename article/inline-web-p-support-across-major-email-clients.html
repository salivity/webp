Inline WebP Support Across Major Email Clients

Inline WebP graphics offer superior compression, reduced file sizes, and transparency support, but their rendering varies dramatically across different email clients. While webmail and modern mobile environments widely embrace the format, legacy desktop clients create significant compatibility hurdles. This article breaks down how major webmail, desktop, and mobile email applications display inline WebP images and outlines how to handle rendering inconsistencies across subscriber inboxes.

Webmail Clients

Webmail platforms largely rely on the rendering engine of the web browser displaying them, resulting in high compatibility for WebP:

  • Gmail (Web): Gmail natively supports WebP across all modern browsers. Even when passing images through Google’s image caching proxy, WebP files are preserved and displayed correctly.
  • Outlook.com: Because it runs within modern web browsers, Outlook on the web consistently renders inline WebP images without issue.
  • Yahoo! Mail and AOL: Both platforms display WebP graphics reliably, matching the host browser's image decoding capabilities.

Desktop Clients

Desktop email clients present the starkest divide in WebP compatibility:

  • Apple Mail (macOS): Full support was introduced starting with macOS 11 (Big Sur). Apple Mail uses the WebKit engine to decode and display inline WebP graphics just like standard JPEGs or PNGs.
  • Microsoft Outlook for Windows (Classic): This client does not support WebP. Older and traditional standalone versions of Outlook for Windows (2016, 2019, 2021, and Microsoft 365 classic) use the Microsoft Word rendering engine, which fails to decode WebP, resulting in broken image icons or empty boxes.
  • The "New" Outlook for Windows: Built on web technologies using Microsoft Edge/Chromium, the new Outlook interface does display WebP images properly.
  • Mozilla Thunderbird: Thunderbird uses the Gecko layout engine (the core of Firefox), providing native, consistent rendering of WebP graphics across Windows, macOS, and Linux.

Mobile Clients

Mobile support is generally robust due to modern smartphone operating systems:

  • Apple Mail (iOS/iPadOS): Apple introduced native WebP support in iOS 14. Modern iPhone and iPad users will see inline WebP assets render smoothly.
  • Gmail App (Android and iOS): On Android, WebP has been an operating system-level standard for years, ensuring reliable display. The iOS Gmail app also handles WebP appropriately using updated system web components.
  • Samsung Email: Like the Gmail app, Samsung’s native email client easily displays WebP through the underlying Android Chromium WebView.

Strategic Implementation and Fallbacks

Because classic desktop versions of Microsoft Outlook remain widely used in corporate and B2B environments, relying exclusively on WebP in email templates remains a risk.

To mitigate rendering issues:

  • Use the <picture> tag: Provide a WebP source alongside a standard JPEG or PNG fallback for broader client compatibility.
  • Apply MSO Conditional Comments: Hide WebP elements from Outlook desktop clients and explicitly serve standard PNG or JPEG fallbacks using <!--[if mso]> conditional blocks.
  • Analyze Your Audience: In B2C environments dominated by mobile devices and webmail, WebP adoption presents minimal risk. In B2B sectors with high desktop Outlook adoption, traditional formats remain the safer default.
