Decompose Animated WebP into Frame Buffers

This article provides an overview of the programmatic tools and libraries available to decompose animated WebP files into individual, fully rendered frame buffers. Because animated WebP files utilize canvas-based delta encoding, frame disposal, and alpha blending across sequences, extracting usable frames requires decoding them against a virtual canvas rather than simply extracting raw data chunks. Below are the primary libraries across multiple programming languages that properly handle the animation state machine and produce raw pixel buffers for each frame.

C / C++: libwebp (libwebpdemux)

The official reference implementation from Google provides the standard decoder via the libwebpdemux library.

  • API: WebPAnimDecoder
  • Mechanism: Rather than manually tracking canvas sizes, offsets, and disposal methods, the WebPAnimDecoder API automatically manages the internal canvas state. It sequentially composites sub-frame patches, applies blending operations, and exposes the fully reconstructed frame as a raw RGBA or BGRA buffer alongside its timestamp and duration.
  • Best For: High-performance native applications, system services, and as the underlying engine for wrappers in other languages.

Rust: webp-animation and image

Rust developers have access to both low-level bindings and pure-Rust decoders.

  • webp-animation: A safe wrapper around Google's libwebp and libwebpdemux. It utilizes Decoder to read input bytes and yields an iterator of frames. Each frame provides a timestamp and a raw pixel slice (&[u8]) representing the full RGBA canvas for that specific point in time.
  • image: The standard Rust image processing crate supports WebP. While primarily used for static images, its ongoing format extensions allow access to frame iterators for multi-frame images, producing dynamic image buffers containing raw pixel data.

Python: Pillow and pywebp

Python offers both high-level image manipulation and direct C bindings.

  • Pillow (PIL Fork): Pillow natively supports animated WebP files when compiled with WebP support. By opening an image and using ImageSequence.Iterator(image), you can step through every frame. Pillow automatically handles frame disposal and composition on the canvas. Calling .convert("RGBA").tobytes() on each frame yields the raw pixel buffer.
  • libwebp bindings (webp / pywebp): Several PyPI packages bind directly to WebPAnimDecoder. These wrappers bypass the higher-level PIL overhead, streaming raw memory buffers directly into Python bytes or NumPy arrays.

Node.js / JavaScript: Sharp and webp-demux

In the Node.js ecosystem, native addons provide the fastest route to individual frame buffers.

  • Sharp: Powered by libvips, Sharp can read animated WebP files by setting the { pages: -1 } option upon loading. This loads all frames into memory. Developers can extract each frame individually, crop to the canvas boundaries, and output raw pixel data via .raw().toBuffer().
  • WebAssembly (Wasm) libwebp builds: For browser environments or environments without native node-gyp bindings, compiling libwebpdemux to WebAssembly allows developers to unpack frames into raw ImageData or Uint8ClampedArray buffers directly on the client side.

Go: cgo libwebp wrappers

While Go's native golang.org/x/image/webp package historically focuses on basic, static WebP decoding, animated decomposition is achieved via Cgo wrappers.

  • github.com/sizeofint/webpanimation: A Go wrapper around libwebpdemux designed specifically for animated WebP rendering. It steps through frames using an iterator pattern, returning the decoded image data as standard Go image.RGBA structs, which expose the underlying pixel slice directly via the Pix slice buffer.
