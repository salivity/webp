WebP Browser Support Milestones and Adoption

This article examines the critical browser support milestones that transformed Google’s WebP image format from an experimental alternative into a universal web standard. By tracing the adoption timeline across major rendering engines—culminating in key updates from Microsoft, Mozilla, and Apple—we explore the exact turning points that enabled developers to serve WebP without relying heavily on legacy fallbacks.

The Chrome and Chromium Foundation (2010–2013)

Google introduced WebP in 2010 to reduce image payload sizes without sacrificing visual fidelity. Google Chrome gained native WebP decoding in 2011 (Chrome 9 for lossy, Chrome 23 for lossless and transparency). Opera adopted WebP shortly thereafter when it migrated to the Chromium-based Blink engine in 2013 with Opera 15. While this gave WebP significant market share through sheer volume of Chrome users, the format remained largely impractical as a single-source format due to resistance from other major browser vendors.

The Microsoft Edge Shift (2018–2020)

Microsoft was the first non-Google platform vendor to shift stance. EdgeHTML 18 introduced native WebP decoding in October 2018 with the Windows 10 October 2018 Update. However, the true milestone for Microsoft’s ecosystem arrived in January 2020 with the release of the Chromium-powered Microsoft Edge (Edge 79). This transition unified Edge's media engine with Blink, ensuring seamless feature parity for WebP animations, alpha transparency, and lossy/lossless modes across Windows and macOS installations.

Firefox 65 Removes the Gecko Barrier (January 2019)

Mozilla resisted WebP for nearly a decade, debating its compression advantages versus format fragmentation. That stance changed with the release of Firefox 65 in January 2019, which enabled native WebP support across desktop and Android platforms. Firefox’s integration proved crucial because it demonstrated that non-Chromium independent browser engines recognized WebP’s performance dividends. With Firefox aboard, global browser support crossed the 75% threshold, making WebP delivery via the <picture> element standard practice for web performance optimization.

Safari 14: The Final Frontier for Parity (September 2020)

Apple’s Safari was the final and most significant barrier to universal WebP adoption. Because iOS restricts all third-party mobile browsers to Apple’s WebKit engine, the absence of WebP support in Safari meant that hundreds of millions of mobile users could not view WebP assets natively.

The decisive tipping point occurred with the release of Safari 14 in September 2020 on iOS 14 and iPadOS 14, followed shortly by its availability on macOS Big Sur and macOS Catalina. Safari 14 introduced native support for both lossy and lossless WebP images. This update resolved the mobile Safari bottleneck and immediately propelled global WebP support beyond 90%.

Universal Mainstream Baseline

By late 2020, all four dominant browser engines—Blink, Gecko, WebKit, and modern Edge—offered full support parity for WebP decoding. This unified support allowed content delivery networks (CDNs), modern content management systems, and web frameworks to transition WebP from an optional progressive enhancement into a safe, primary default format for web delivery.
