WebP Magic Bytes: How to Verify a WebP File

Verifying an authentic WebP image requires inspecting the binary header of the file rather than relying strictly on the .webp file extension. Because WebP is built on the Resource Interchange File Format (RIFF) container, a genuine WebP file contains a distinct 12-byte header signature split into two distinct identifiers. This guide covers the exact magic byte sequence, byte offsets, and chunk headers necessary to confirm that a file is a valid WebP image.

The 12-Byte Header Signature

A valid WebP file does not use a single, continuous string of bytes at index 0. Instead, it places verification data across the first 12 bytes:

  • Bytes 0–3 (Offset 0x00): Must contain the ASCII string RIFF (Hex: 52 49 46 46).
  • Bytes 4–7 (Offset 0x04): A 32-bit little-endian integer representing the total file size minus 8 bytes. Because this value changes with every file, it cannot be matched against a static byte sequence.
  • Bytes 8–11 (Offset 0x08): Must contain the ASCII string WEBP (Hex: 57 45 42 50).

To conclusively verify that a file is a WebP image, you must check both that bytes 0–3 equal RIFF and that bytes 8–11 equal WEBP.

WebP Format Chunks

Immediately following the WEBP identifier at byte 12 (Offset 0x0C), the file declares the internal WebP format variant. Inspecting these bytes provides additional validation of the file's structure:

  • VP8 (Hex: 56 50 38 20): Identifies lossy WebP compression. Note the trailing ASCII space.
  • VP8L (Hex: 56 50 38 4C): Identifies lossless WebP compression.
  • VP8X (Hex: 56 50 38 58): Identifies an extended WebP format, used for animations, ICC color profiles, EXIF metadata, or alpha transparency.

Hex Representation Example

When inspecting a standard lossy WebP file in a hex editor, the first 16 bytes will appear in this format:

52 49 46 46 [XX XX XX XX] 57 45 42 50 56 50 38 20
 R  I  F  F  (File Size)   W  E  B  P  V  P  8  _

Any file that lacks RIFF at offset 0 and WEBP at offset 8 is not an authentic WebP image.
