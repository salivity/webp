Can Animated WebP Frames Vary in Size and Position?

Animated WebP files fully support individual frames that vary in both dimensions and canvas location from one frame to the next. Rather than requiring every frame to match the full canvas dimensions, the WebP specification allows sub-frames with custom offsets, enabling encoders to update only the specific regions of an image that change over time. This targeted updating dramatically reduces overall file sizes while preserving full visual fidelity.

The Mechanism: The ANMF Chunk

The WebP container specification defines animations using an overall canvas size alongside individual animation frame chunks known as ANMF chunks. While the global canvas defines the total display width and height of the animation, each ANMF chunk defines its own local parameters:

  • Frame X and Frame Y: Pixel offsets determining where the top-left corner of the sub-frame is placed relative to the global canvas.
  • Frame Width and Frame Height: The exact pixel dimensions of the current frame data, which can be smaller than the global canvas.
  • Duration: How long the sub-frame should remain visible.

Because of this structure, a 1000x1000 canvas can display a frame that is only 50x50 pixels located at coordinates (300, 450), leaving the rest of the canvas unchanged.

Blending and Disposal Methods

To correctly handle sub-frames of varying sizes and locations, WebP relies on blending and disposal instructions defined per frame:

  • Blending Method: Determines whether the current frame is drawn directly over the existing canvas using alpha compositing, or if it replaces the pixels within its bounding box entirely without blending.
  • Disposal Method: Instructs the decoder on what to do after the frame duration ends. The canvas area covered by the frame can either be retained for the next frame or disposed of by clearing it back to the background color.

Why Varying Frame Sizes Matter

This capability functions as a modern form of differential encoding, often referred to as "dirty rectangles." In typical animations, large sections of the background remain static while only a small element moves.

By cropping each frame down to only the area containing visual changes and positioning it using X/Y coordinates, encoders eliminate redundant data. When combined with WebP’s native lossy (VP8) or lossless (VP8L) compression, varying sub-frame sizes make animated WebP files significantly smaller and faster to load than legacy formats like animated GIF. Modern web browsers and image viewers natively support these decoding operations seamlessly.
