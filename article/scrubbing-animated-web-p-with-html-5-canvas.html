Scrubbing Animated WebP with HTML5 Canvas

Animated WebP files provide superior compression compared to traditional GIFs, but standard web implementations lack native controls for interactive scrubbing, seeking, or reverse playback. Because the HTML <img> tag treats animated WebP as a continuous, uncontrolled loop, developers must intercept the individual frame data and render it onto an HTML5 <canvas>. By parsing the WebP container, decoding its constituent frames into memory, and mapping a user input like a slider to the canvas render loop, you can achieve smooth, frame-by-frame scrubbing.

The Challenge with Native WebP Playback

Browsers lack an API to control the playback timeline of animated images directly. While the HTML5 <video> element provides a .currentTime property for seeking, standard animated WebP elements do not expose playback position, duration, or individual frame indices to JavaScript. To enable scrubbing, the WebP file must be demuxed and decoded into discrete image buffers that the HTML5 2D rendering context can draw on demand.

Step 1: Parsing and Demuxing the WebP Container

An animated WebP file uses the RIFF container format, packing metadata (VP8X), frame positioning, duration (ANMF), and raw image payloads (VP8 or VP8L). To read these frames:

  1. Fetch the Binary Data: Download the file as an ArrayBuffer using the fetch API.
  2. Decode via WebAssembly or JavaScript: Use a dedicated demuxer library (such as a WebAssembly-compiled build of Google's official libwebp or a pure JavaScript parser) to traverse the RIFF chunks and extract the raw frame payloads alongside their frame delays and blend modes.
  3. Handle Disposal and Blending: Animated WebP frames can be smaller sub-rectangles of the total canvas that either blend with the previous frame or overwrite it. The parser must account for these disposal methods to construct the correct visual output for each frame.

Step 2: Storing Frames in Memory

Once frames are resolved into complete images, convert them into high-performance graphical representations. Avoid keeping raw canvas instances for each frame, as this rapidly exhausts browser memory. Instead, create ImageBitmap objects:

// Example of converting decoded frame pixel data to ImageBitmap
async function cacheFrames(decodedFrames) {
  const frameBitmaps = [];
  for (const frame of decodedFrames) {
    const bitmap = await createImageBitmap(frame.imageData);
    frameBitmaps.push({
      bitmap,
      duration: frame.duration
    });
  }
  return frameBitmaps;
}

ImageBitmap objects are stored in GPU-friendly memory and allow for asynchronous, non-blocking rendering using the canvas API.

Step 3: Mapping Input to Canvas Rendering

With the frame array established, connect the canvas drawing mechanism to an input mechanism, such as an <input type="range">, a mouse drag event, or a scroll position.

const canvas = document.getElementById('scrubCanvas');
const ctx = canvas.getContext('2d');
const scrubber = document.getElementById('scrubRange');

let currentFrameIndex = 0;
let frames = []; // Populated with cached ImageBitmap objects

function renderFrame(index) {
  if (!frames[index]) return;
  
  // Clear the canvas and draw the selected frame
  ctx.clearRect(0, 0, canvas.width, canvas.height);
  ctx.drawImage(frames[index].bitmap, 0, 0);
}

scrubber.addEventListener('input', (e) => {
  const progress = parseFloat(e.target.value); // Value between 0 and 1
  currentFrameIndex = Math.floor(progress * (frames.length - 1));
  
  requestAnimationFrame(() => renderFrame(currentFrameIndex));
});

Using requestAnimationFrame ensures that the canvas only redraws during the browser's refresh cycles, preventing rendering bottlenecks during rapid mouse or touch scrubbing.

Performance and Memory Optimization

To keep scrubbing responsive on mobile devices and low-spec hardware:

  • Downsample on Ingestion: If the animated WebP is displayed at a fixed size smaller than its source, pass resize options into createImageBitmap() during decoding to reduce memory usage.
  • Release Bitmap Resources: Call .close() on ImageBitmap objects when the player component unmounts to prevent memory leaks.
  • Use an OffscreenCanvas: For complex decoding or post-processing pipelines, execute decoding and canvas preparation inside a Web Worker using OffscreenCanvas to prevent frame drops on the main UI thread.
