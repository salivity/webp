How to Export HTML5 Canvas to WebP

The HTML5 canvas element can export drawings directly to the WebP format natively using JavaScript without requiring third-party encoding libraries. By utilizing the built-in HTMLCanvasElement.toDataURL() or HTMLCanvasElement.toBlob() methods and passing image/webp as the MIME type parameter, modern web browsers compress the canvas bitmap directly into WebP. This article explains how to implement these methods, adjust compression quality, and handle browser fallbacks effectively.

Using toDataURL() for Data URIs

The toDataURL() method synchronously extracts the canvas content as a base64-encoded data URL. To export directly to WebP, provide 'image/webp' as the first argument, and optionally provide an image quality value between 0.0 and 1.0 as the second argument.

const canvas = document.getElementById('myCanvas');

// Export as a WebP data URL with 80% quality
const webpDataUrl = canvas.toDataURL('image/webp', 0.8);

// Use the data URL (e.g., set to an <img> element)
const image = document.getElementById('preview');
image.src = webpDataUrl;

This approach works best for small images or immediate display in an <img> tag, though base64 strings consume roughly 33% more memory than binary data.

Using toBlob() for Binary Files and Uploads

For larger canvas drawings, performance-critical applications, or direct file uploads, toBlob() is the preferred method. It processes the export asynchronously and produces a binary Blob object instead of a string.

const canvas = document.getElementById('myCanvas');

// Export asynchronously as a WebP blob with 90% quality
canvas.toBlob((blob) => {
  if (blob) {
    // Example: Create a download link for the WebP file
    const url = URL.createObjectURL(blob);
    const link = document.createElement('a');
    link.href = url;
    link.download = 'drawing.webp';
    link.click();
    
    // Revoke the object URL to free memory
    URL.revokeObjectURL(url);
  }
}, 'image/webp', 0.9);

The resulting Blob can be transmitted directly to an API via fetch() or FormData using multipart/form-data.

Controlling WebP Compression Quality

The optional quality argument (from 0.0 for maximum compression to 1.0 for maximum quality) directly controls the lossy WebP encoder built into the browser engine:

  • 1.0: Near-lossless output with minimal compression artifacts.
  • 0.8 (Default for most implementations): Optimal balance of high visual fidelity and reduced file size.
  • Below 0.5: Aggressive compression suitable for thumbnails or bandwidth-constrained scenarios.

If the quality parameter is omitted, browsers use their own internal default settings (typically around 0.8 to 0.92).

Browser Compatibility and Fallback Handling

All modern browsers (Chrome, Firefox, Safari 14+, and Edge) support exporting canvas to WebP. However, the HTML5 specification dictates that if a browser does not support the requested MIME type, it must fall back to returning image/png.

You can verify whether a browser supports native WebP export by inspecting the prefix of the returned string:

function checkWebpSupport() {
  const dummyCanvas = document.createElement('canvas');
  dummyCanvas.width = 1;
  dummyCanvas.height = 1;
  return dummyCanvas.toDataURL('image/webp').indexOf('data:image/webp') === 0;
}

If the function returns true, the browser natively encodes to WebP directly from the canvas API.
