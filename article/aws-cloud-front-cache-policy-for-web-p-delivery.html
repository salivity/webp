AWS CloudFront Cache Policy for WebP Delivery

Delivering WebP images dynamically through Amazon CloudFront requires a caching strategy that evaluates whether a client's browser supports modern image formats. This guide explains how to configure CloudFront Cache Policies and Origin Request Policies using the HTTP Accept header, ensuring that compatible browsers receive lightweight WebP files while older browsers receive standard formats like JPEG or PNG without cache collisions.

The Challenge of Dynamic WebP Delivery

When an origin serves different image formats from the same URL based on browser capabilities, CloudFront must not serve a cached WebP image to a client that does not support it. CloudFront determines what to store and serve using the cache key. By default, CloudFront cache keys only include the domain name and the URL path. Without explicit configuration, the first requested version of an image (WebP or legacy) would be cached and delivered to all subsequent visitors regardless of their browser support.

Creating the CloudFront Cache Policy

To ensure correct delivery, the cache key must vary based on client capabilities. Because browsers declare support via the Accept request header, CloudFront must incorporate this signal into its cache key.

  1. Open the CloudFront Console and navigate to Policies > Cache.
  2. Click Create cache policy.
  3. Under Cache key settings, locate the Headers dropdown and select Include the following headers.
  4. Add the Accept header to the list.
  5. Configure your desired Minimum, Maximum, and Default TTL values.
  6. Save the policy and attach it to your distribution’s image cache behavior.

Managing Cache Hit Ratios with Header Normalization

While adding the raw Accept header to a custom cache policy guarantees correct image delivery, it introduces a significant performance drawback: different browsers send widely varying Accept strings (e.g., listing various combinations of AVIF, WebP, APNG, and quality weights). This causes CloudFront to treat each browser variant as a unique cache entry, drastically reducing your cache hit ratio.

To maximize caching efficiency while maintaining correct delivery, the industry-standard approach uses a lightweight CloudFront Function on the Viewer Request event to normalize the request:

  1. Viewer Request (CloudFront Function): Inspect the incoming Accept header. If it contains image/webp, set a custom header, such as x-webp-support: true. If not, set it to false.
  2. Custom Cache Policy: Configure CloudFront to cache based on the custom x-webp-support header instead of the raw Accept header.
  3. Origin Request Policy: Forward the x-webp-support (or the original Accept) header to your origin server so it knows which image format to generate and return.

This normalization restricts the cache to only two variants per image (WebP-supported and non-supported), maximizing the cache hit ratio across all global edge locations.

Setting the Vary Header at the Origin

In addition to CloudFront policies, your origin server must include the Vary: Accept (or Vary: x-webp-support) response header. This prevents intermediate proxy caches and downstream browser caches from serving the incorrect format to users who share a network.
