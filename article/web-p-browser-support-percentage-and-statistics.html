WebP Browser Support Percentage and Statistics

Today, the WebP image format is natively supported by approximately 96% to 97% of global web browser traffic. This article covers the current browser support statistics for WebP, outlines which major platforms render it natively, and explains how developers can handle the remaining unsupported traffic.

Current Global Support Statistics

According to browser usage data from Can I Use, WebP has achieved near-universal adoption, boasting native support across roughly 96.6% of tracked global desktop and mobile web users. This high adoption rate makes WebP a safe, highly effective default format for web imagery compared to traditional formats like JPEG and PNG.

Supported Browsers

Virtually every modern web browser supports WebP natively on both desktop and mobile platforms:

  • Google Chrome: Supported natively since version 32 (released in 2014), with early support dating back to version 9.
  • Apple Safari: Supported natively since Safari 14, released alongside iOS 14 and macOS 11 Big Sur in late 2020.
  • Mozilla Firefox: Supported natively since version 65, released in early 2019.
  • Microsoft Edge: Fully supported across all versions built on Chromium, as well as Edge Legacy from version 18.
  • Opera: Supported natively since version 19.
  • Mobile Platforms: Chrome for Android, Safari on iOS (iOS 14+), Samsung Internet, and UC Browser all provide native WebP decoding.

The Unsupported 3% to 4%

The small percentage of global traffic that cannot render WebP consists primarily of outdated software and legacy operating systems:

  • Internet Explorer 11: Microsoft's retired browser never received WebP support and represents the largest historical barrier to 100% adoption.
  • Legacy Apple Devices: Devices stuck on iOS 13 or earlier, and Macs running macOS Catalina (10.15) or older using older versions of Safari.
  • Niche or Embedded Browsers: Specialized web-view environments, legacy feature-phone browsers, and outdated e-readers.

Implementation Best Practices

Because a small segment of users still browses on legacy software, the standard method for delivering WebP is through the HTML5 <picture> element. This technique provides the modern WebP asset to compatible browsers while falling back to JPEG or PNG for the remaining traffic:

<picture>
  <source srcset="image.webp" type="image/webp">
  <img src="image.jpg" alt="Example image description">
</picture>

Alternatively, server-side content negotiation can examine the browser's Accept HTTP header. If the header includes image/webp, the server returns the WebP version; otherwise, it delivers the fallback format under the same URL.
