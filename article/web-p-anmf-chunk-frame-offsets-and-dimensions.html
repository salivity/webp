WebP ANMF Chunk Frame Offsets and Dimensions

This article explains how animated WebP images use the ANMF (Animation Frame) chunk to define the spatial positioning and dimensions of individual frames. Readers will learn the precise binary layout used to encode frame coordinates and sizes, including the specific byte lengths, arithmetic offsets, and decoding rules defined by the WebP container specification.

The ANMF Chunk Layout

In an animated WebP file, each frame is encapsulated within an ANMF chunk defined inside the standard RIFF container. The chunk begins with the 4-byte ASCII FourCC identifier 'ANMF', followed by a 4-byte unsigned integer indicating the size of the chunk payload.

Immediately following the chunk header is a fixed 16-byte frame header containing metadata for positioning, sizing, duration, and rendering flags. The first 12 bytes of this header are dedicated exclusively to frame offsets and dimensions, structured as four consecutive 24-bit (3-byte) unsigned, little-endian integers.

Frame Offsets: Frame X and Frame Y

The position of a frame is defined relative to the upper-left corner of the global animation canvas (coordinate 0, 0).

  • Frame X (Bytes 0–2): A 24-bit unsigned integer representing the horizontal offset. The actual pixel offset from the left edge of the canvas is calculated as: \[\text{Actual X Offset} = \text{Frame X} \times 2\]
  • Frame Y (Bytes 3–5): A 24-bit unsigned integer representing the vertical offset. The actual pixel offset from the top edge of the canvas is calculated as: \[\text{Actual Y Offset} = \text{Frame Y} \times 2\]

Because both coordinates are multiplied by 2, the horizontal and vertical start positions are always aligned to even pixel coordinates. This scaling factor accommodates large canvas dimensions while conserving byte size in the chunk structure.

Frame Dimensions: Width and Height

Following the offsets, the frame header specifies the dimensions of the sub-frame image data.

  • Frame Width (Bytes 6–8): A 24-bit unsigned integer representing the width of the frame. Because a frame cannot have a width of zero pixels, the value is 1-based: \[\text{Actual Frame Width} = 1 + \text{Frame Width}\]
  • Frame Height (Bytes 9–11): A 24-bit unsigned integer representing the height of the frame, also 1-based: \[\text{Actual Frame Height} = 1 + \text{Frame Height}\]

Canvas Boundary Constraints

The decoded offsets and dimensions must adhere to the boundaries of the canvas declared in the file's primary VP8X chunk. A parser verifies that the sub-frame fits entirely within the total canvas area using the following rules:

  1. \(\text{Actual X Offset} + \text{Actual Frame Width} \le \text{Canvas Width}\)
  2. \(\text{Actual Y Offset} + \text{Actual Frame Height} \le \text{Canvas Height}\)

By allowing individual frames to have independent offsets and dimensions smaller than the full canvas, WebP supports partial-frame updates. Instead of redrawing the entire screen on each frame, the format only transmits and renders the bounding rectangle containing the changed pixels.
