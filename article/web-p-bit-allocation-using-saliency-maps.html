WebP Bit Allocation Using Saliency Maps

WebP encoders can utilize eye-tracking saliency maps to dynamically allocate local bit distribution, but doing so requires custom encoding pipelines rather than off-the-shelf software tools. By mapping human visual attention to the underlying macroblock architecture of WebP, encoders can preserve high fidelity in visually critical regions while aggressively compressing background areas. This article explores the technical mechanics of integrating saliency maps into WebP, the architectural constraints of the format, and how bit distribution is adjusted at the block level.

The Underlying WebP Architecture

WebP lossy compression is built on the VP8 video codec container. In this format, images are divided into 16x16 macroblocks, which are further divided into 4x4 sub-blocks for prediction and discrete cosine transform (DCT) coding.

To control local bit distribution, WebP utilizes VP8’s segment feature. A WebP frame can define up to four distinct segments. Each segment can be assigned independent parameters, including:

  • Quantization index offsets (adjusting local compression quality)
  • Loop filter strength (controlling edge smoothing)

Because bit distribution cannot be modulated continuously per pixel, any local rate-distortion optimization must operate through these macroblock-level segments.

Integrating Saliency Maps into Encoding

Standard encoders like Google’s cwebp compute spatial complexity internally (variance of luminance and chrominance) to assign macroblocks to these four segments. To use eye-tracking saliency data, this internal heuristic must be replaced or augmented by an external attention map:

  1. Saliency Map Generation: An eye-tracking heat map or a predictive neural network (e.g., DeepGaze) produces a continuous-value visual attention map corresponding to the source image dimensions.
  2. Macroblock Downsampling: The continuous map is downsampled into 16x16 blocks, calculating a mean saliency score for each macroblock.
  3. Quantile Clustering: Because WebP only supports four segments, the macroblock saliency scores must be quantized into four discrete tiers (e.g., high focus, secondary focus, peripheral, and background).
  4. Segment Assignment: The encoder maps each macroblock to its respective segment ID and applies negative quantization offsets to high-saliency segments (increasing bit allocation) and positive offsets to low-saliency segments (reducing bit allocation).

Technical Limitations and Artifacts

While feasible, using saliency-guided bit distribution in WebP involves distinct architectural trade-offs:

  • The Four-Segment Ceiling: Newer formats like AV1 or JPEG XL permit fine-grained, localized delta-quantization across many levels. WebP’s hard limit of four segments restricts gradient smoothness across the transitions between salient and non-salient regions.
  • Boundary Discontinuities: Overly aggressive bit starvation in low-saliency segments can cause blocking artifacts directly adjacent to sharp, high-fidelity salient blocks. Loop filtering must be tuned carefully across segment boundaries to mask these transitions.
  • Lossless Incompatibility: This approach applies strictly to lossy WebP. WebP Lossless relies on spatial transforms, color indexing, and entropy coding without VP8 macroblock segmentation, making region-based quantization allocation inapplicable.

Current Implementation Status

Mainstream builds of libwebp do not include direct command-line arguments to ingest external saliency maps. Implementing this workflow requires modifying the segment analysis phase inside libwebp source code (specifically within src/enc/analysis_enc.c) to read external spatial weighting arrays prior to rate-distortion optimization loops. When implemented, it yields measurable perceptual bitrate savings without lowering the subjective quality perceived by human observers.
