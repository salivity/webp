Can You Embed WebP in PDF Without Conversion?

WebP images cannot be embedded directly into a PDF document as visible page elements without prior conversion. The official PDF specification does not support the WebP compression format, meaning standard PDF viewers cannot parse or display raw WebP data. To display a WebP image inside a PDF, the file must first be converted into a natively supported format, such as JPEG, JPEG 2000, or a Flate-compressed raster bitmap.

The PDF Standard and Supported Formats

The PDF standard (ISO 32000) defines exact image compression filters that PDF readers must recognize. These native filters include:

  • DCTDecode: Standard JPEG compression
  • JPXDecode: JPEG 2000 compression
  • FlateDecode: Lossless zlib/deflate compression (used for PNG-style raster images)
  • CCITTFaxDecode and JBIG2Decode: Formats designed for monochrome images

Because WebP is not listed among the recognized image compression filters in either PDF 1.7 or PDF 2.0, a PDF reader has no built-in mechanism to decode and render a raw WebP stream on a page.

How PDF Tools Handle WebP Files

When a PDF editor, virtual printer, or document generation library (such as ReportLab, PDFKit, or Adobe Acrobat) allows you to insert a WebP file, it does not embed the native WebP file directly. Instead, the application automatically performs an internal conversion during the build process:

  1. The software decodes the WebP file into raw pixel data in memory.
  2. It re-encodes the pixel data into a standard PDF-compliant format—typically JPEG for lossy WebP files or Flate/raw bitmap for lossless WebP files.
  3. The newly encoded stream is written into the PDF's image object.

This process ensures that any standard PDF reader can open and view the document, but it means the original WebP data is not retained in its native form on the page.

The Exception: File Attachments

The only way to embed an unconverted WebP file directly into a PDF is as an arbitrary file attachment (EmbeddedFiles stream). In this scenario, the WebP file remains bit-for-bit identical to the original and is stored within the PDF container. However, it exists solely as an attachment for the user to extract or download; it will not render visually as an image on the document pages.

Best Practices for Using WebP in PDF Workflows

Because conversion must happen at some stage, you should handle the conversion deliberately to maintain image quality and optimize file size:

  • For photographic images: Convert lossy WebP files to high-quality JPEG or JPEG 2000 before embedding.
  • For graphics and illustrations: Convert lossless WebP files with transparency to PNG, which translates directly to a PDF image object with an Alpha Soft Mask (SMask).
  • Automated pipelines: If using automated document generation, use an imaging library to convert WebP inputs to standard streams explicitly, preventing unexpected bloat caused by uncompressed fallback streams.
