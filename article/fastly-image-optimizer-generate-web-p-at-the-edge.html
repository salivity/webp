Fastly Image Optimizer: Generate WebP at the Edge

Fastly leverages its Image Optimizer (IO) to dynamically convert source images into lightweight WebP assets directly on its edge cloud platform. By intercepting incoming media requests, detecting browser capabilities, and performing real-time image transformations close to end users, Fastly delivers optimized, format-efficient graphics without burdening origin infrastructure or requiring manual pre-generation of assets.

Automated Browser Capability Detection

Fastly’s edge nodes inspect the HTTP Accept request header sent by the client's browser. Modern browsers indicate support for WebP by including image/webp in this header. Fastly uses this signal to determine whether the requested asset can be served as a WebP file or if it should remain in a legacy format like JPEG or PNG for older clients that lack support.

The Transformation Workflow

When a user requests an image, the process unfolds at the edge:

  1. Request Inspection: The edge server receives the image request and checks for format parameters (such as auto=webp or specific quality settings) in the query string or configured Varnish Configuration Language (VCL) / Compute logic.
  2. Cache Check: Fastly checks its local edge cache to see if the requested asset—already transformed into WebP—exists. If cached, it is served immediately.
  3. Origin Fetch and Transformation: If the asset is not cached, Fastly fetches the high-resolution source image from the origin server. The edge processor decodes the original image, applies requested resizing or compression, and encodes the output into WebP directly in memory.
  4. Caching and Delivery: The newly generated WebP image is cached at the edge to serve subsequent requests and simultaneously delivered to the client.

Parameter-Driven Optimization

Fastly allows developers to enable automatic format selection using simple query parameters. Appending auto=webp to an image URL instructs the Fastly Image Optimizer to automatically serve a WebP version if the client supports it, while safely falling back to the original format if it does not. Developers can combine this with additional parameters, such as quality, width, and height, to fine-tune visual fidelity and asset dimensions dynamically.

Key Benefits of Edge-Generated WebP

  • Bandwidth Reduction: WebP images are typically 25% to 35% smaller than comparable JPEGs and PNGs, drastically reducing data transfer costs.
  • Origin Offloading: Because transformations occur within Fastly's edge environment, the origin server only stores a single master copy of each image, eliminating the need to store and manage multiple file formats.
  • Faster Page Speeds: Delivering smaller files from the nearest edge point of presence (PoP) reduces latency and improves Core Web Vitals, specifically Largest Contentful Paint (LCP).
