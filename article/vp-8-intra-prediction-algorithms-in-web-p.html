VP8 Intra-Prediction Algorithms in WebP

WebP's lossy image compression relies on the VP8 keyframe intra-prediction framework to eliminate spatial redundancy prior to transform coding and quantization. By analyzing previously decoded adjacent boundary pixels to the top and left of a target block, the codec models the current block's texture without transmitting raw pixel values. This article breaks down the mathematical formulations and algorithms governing the primary VP8 intra-prediction modes used inside WebP, covering both macroblock-level predictions and directional 4x4 sub-block operations.

Macroblock Partitioning and Reference Pixels

VP8 processes images using \(16 \times 16\) macroblocks for luma (brightness) and \(8 \times 8\) blocks for chroma (color difference). Intra-prediction relies entirely on the reconstructed pixels immediately adjacent to the current block:

  • Above reference vector (\(A\)): \(A_x\) where \(x \in [0, N-1]\), situated at row \(y = -1\).
  • Left reference vector (\(L\)): \(L_y\) where \(y \in [0, N-1]\), situated at column \(x = -1\).
  • Top-left reference pixel (\(P_{-1, -1}\)): The diagonal corner pixel at \((-1, -1)\).

For luma components, prediction occurs at either the full \(16 \times 16\) macroblock level or via sixteen individual \(4 \times 4\) sub-blocks. Chroma components (\(U\) and \(V\)) are always predicted at the \(8 \times 8\) block level.

16x16 and 8x8 Intra-Prediction Modes

VP8 specifies four standard prediction modes for \(16 \times 16\) luma macroblocks and \(8 \times 8\) chroma blocks.

1. DC Prediction (DC_PRED)

DC prediction fills the target block with a single uniform scalar value equal to the rounded arithmetic mean of the available adjacent reference pixels.

When both top and left boundaries are present:

\[\mu = \frac{\sum_{x=0}^{N-1} A_x + \sum_{y=0}^{N-1} L_y + N}{2N}\]

In fixed-point integer arithmetic for a \(16 \times 16\) block (\(N=16\)), this is calculated as:

\[P(x, y) = \left( \sum_{x=0}^{15} A_x + \sum_{y=0}^{15} L_y + 16 \right) \gg 5\]

For an \(8 \times 8\) block (\(N=8\)):

\[P(x, y) = \left( \sum_{x=0}^{7} A_x + \sum_{y=0}^{7} L_y + 8 \right) \gg 4\]

If boundary pixels are missing due to image borders:

  • Only Above Available: \(P(x, y) = \left( \sum A_x + (N \gg 1) \right) \gg \log_2(N)\)
  • Only Left Available: \(P(x, y) = \left( \sum L_y + (N \gg 1) \right) \gg \log_2(N)\)
  • Neither Available: \(P(x, y) = 128\) (mid-range gray for 8-bit depth).

2. Vertical Prediction (V_PRED)

Vertical prediction models structures that continue vertically downward. The values of the above boundary row are replicated down each column:

\[P(x, y) = A_x \quad \text{for } x, y \in [0, N-1]\]

3. Horizontal Prediction (H_PRED)

Horizontal prediction projects values horizontally across each row from the left boundary column:

\[P(x, y) = L_y \quad \text{for } x, y \in [0, N-1]\]

4. TrueMotion Prediction (TM_PRED)

TrueMotion is a proprietary VP8 mode designed to model linear brightness gradients. It combines horizontal and vertical differentials relative to the top-left boundary pixel \(P_{-1, -1}\). The base mathematical form is:

\[P(x, y) = \text{Clip1}(L_y + A_x - P_{-1, -1})\]

Where \(\text{Clip1}(v)\) restricts the calculated value to the valid 8-bit unsigned integer range:

\[\text{Clip1}(v) = \max(0, \min(255, v))\]

If \(L_y\) differs from the corner pixel by \(\Delta L\), that same differential is applied across \(A_x\), preserving two-dimensional planar shifts.

4x4 Luma Intra-Prediction Modes

When an image contains high-frequency details, a \(16 \times 16\) block is decomposed into sixteen \(4 \times 4\) sub-blocks. VP8 defines ten distinct sub-block prediction modes (B-modes). In addition to 4x4 adaptations of DC, Vertical, Horizontal, and TrueMotion, six directional modes extrapolate boundary edges at specific geometric angles using weighted linear interpolation filters.

These directional modes reference:

  • Top reference pixels: \(A_0, A_1, A_2, A_3\) and extended pixels \(A_4, A_5, A_6, A_7\).
  • Left reference pixels: \(L_0, L_1, L_2, L_3\).
  • Top-left reference pixel: \(P_{-1, -1}\) (denoted here as \(C\)).

1. B_LD_PRED (Left-Down Directional)

Interpolates downward-left at approximately a 45-degree angle using a 3-tap smoothing filter with weights \([1, 2, 1]\):

\[P(x, y) = \begin{cases} (A_{x+y} + 2A_{x+y+1} + A_{x+y+2} + 2) \gg 2 & \text{if } x + y < 6 \\ (A_6 + 2A_7 + A_7 + 2) \gg 2 & \text{if } x + y = 6 \\ A_7 & \text{if } x + y > 6 \end{cases}\]

2. B_RD_PRED (Right-Down Directional)

Predicts diagonally along a 45-degree angle from the top-left down toward the bottom-right. Depending on the coordinate offset \(x - y\), it interpolates either across \(A\), \(L\), or through the corner pixel \(C\):

\[P(x, y) = \begin{cases} (A_{x-y-1} + 2A_{x-y} + A_{x-y+1} + 2) \gg 2 & \text{if } x > y \\ (L_{y-x-1} + 2L_{y-x} + L_{y-x+1} + 2) \gg 2 & \text{if } x < y \\ (A_0 + 2C + L_0 + 2) \gg 2 & \text{if } x = y \end{cases}\]

(Boundary offsets where index equals \(-1\) map to \(C\).)

3. B_VR_PRED (Vertical-Right Directional)

Extrapolates trajectories at an angle of roughly 26.6 degrees to the right of vertical (\(\tan^{-1}(0.5)\)). The equation branches on whether the ray intersects the top row or the left column:

\[z = 2x - y\]

\[P(x, y) = \begin{cases} (A_{x - (y \gg 1) - 1} + A_{x - (y \gg 1)}) \gg 1 & \text{if } z = 0, 2, 4, 6 \text{ and } z \ge 0 \\ (A_{x - (y \gg 1) - 2} + 2A_{x - (y \gg 1) - 1} + A_{x - (y \gg 1)} + 2) \gg 2 & \text{if } z = 1, 3, 5 \text{ and } z > 0 \\ (L_0 + 2C + A_0 + 2) \gg 2 & \text{if } z = -1 \\ (C + 2L_0 + L_1 + 2) \gg 2 & \text{if } z = -2 \end{cases}\]

4. B_VL_PRED (Vertical-Left Directional)

Extrapolates trajectories at an angle of roughly 26.6 degrees to the left of vertical:

\[P(x, y) = \begin{cases} (A_{x + (y \gg 1)} + A_{x + (y \gg 1) + 1} + 1) \gg 1 & \text{if } y \text{ is even} \\ (A_{x + (y \gg 1)} + 2A_{x + (y \gg 1) + 1} + A_{x + (y \gg 1) + 2} + 2) \gg 2 & \text{if } y \text{ is odd} \end{cases}\]

5. B_HD_PRED (Horizontal-Down Directional)

Extrapolates trajectories at roughly 26.6 degrees below horizontal (\(\tan^{-1}(2)\)). Using \(z = 2y - x\):

\[P(x, y) = \begin{cases} (L_{y - (x \gg 1) - 1} + L_{y - (x \gg 1)}) \gg 1 & \text{if } z = 0, 2, 4 \text{ and } z \ge 0 \\ (L_{y - (x \gg 1) - 2} + 2L_{y - (x \gg 1) - 1} + L_{y - (x \gg 1)} + 2) \gg 2 & \text{if } z = 1, 3 \text{ and } z > 0 \\ (L_0 + 2C + A_0 + 2) \gg 2 & \text{if } z = -1 \\ (C + 2A_0 + A_1 + 2) \gg 2 & \text{if } z = -2 \end{cases}\]

6. B_HU_PRED (Horizontal-Up Directional)

Extrapolates trajectories upward toward the right from the left column:

\[z = 2y + x\]

\[P(x, y) = \begin{cases} (L_{y + (x \gg 1)} + L_{y + (x \gg 1) + 1} + 1) \gg 1 & \text{if } z = 0, 2, 4 \\ (L_{y + (x \gg 1)} + 2L_{y + (x \gg 1) + 1} + L_{y + (x \gg 1) + 2} + 2) \gg 2 & \text{if } z = 1, 3 \\ L_3 & \text{if } z \ge 5 \end{cases}\]

Arithmetic Characteristics and Implementation

All VP8 prediction equations are constrained to power-of-two divisions implemented via right-shift bitwise operations (\(\gg\)). The 3-tap smoothing filters rely on the kernel coefficients \([1, 2, 1]\), which are implemented as:

\[f(u, v, w) = (u + (v \ll 1) + w + 2) \gg 2\]

The addition of the constant offset (\(2\) or \(1\)) prior to shifting implements round-half-up integer division. This structure eliminates floating-point indeterminism, guarantees identical decoding across different hardware platforms, and allows parallel execution using single-instruction multiple-data (SIMD) vector registers.
