WebP Alpha Data Chunk Structure in Lossy Images

An alpha data chunk (ALPH) in a lossy WebP image provides transparency information for a lossy VP8 bitstream, which natively does not support an alpha channel. Stored inside an extended WebP container (VP8X), the ALPH chunk consists of a standard RIFF chunk header, a one-byte configuration flag field, and the encoded alpha bitstream. This article details the specific byte layout, bit-level flags, filtering techniques, and compression mechanisms used within the ALPH chunk.

Container Placement

In an extended WebP file, the presence of transparency alongside a lossy stream is indicated by setting the Alpha flag (bit 4) in the VP8X chunk. When present, the ALPH chunk must appear immediately before the VP8 (lossy bitstream) chunk.

The outer layout follows standard RIFF conventions:

  • FourCC: 4 bytes containing the ASCII string 'ALPH'.
  • Chunk Size: 4 bytes (32-bit unsigned integer, little-endian) representing the total size of the chunk payload in bytes, excluding the FourCC and size fields.
  • Payload: The 1-byte header followed by the alpha bitstream.
  • Padding: If the Chunk Size is odd, a single padding byte of 0x00 is appended to align the chunk to an even 2-byte boundary (not counted in Chunk Size).

The Header Byte (Flags)

The first byte of the ALPH chunk payload defines how the subsequent alpha bitstream is processed, filtered, and compressed. It is partitioned into four 2-bit fields:

Bits 0–1: Compression Method

Specifies the compression algorithm used for the alpha payload:

  • 0: No compression. The data contains raw alpha samples.
  • 1: Compressed using the WebP lossless format (VP8L).
  • 2–3: Reserved for future use (must be written as 0 and ignored by decoders).

Bits 2–3: Filtering Method

Applies a spatial prediction filter to decorrelate alpha values before compression:

  • 0: None.
  • 1: Horizontal filter (predicts pixel value based on the pixel immediately to the left).
  • 2: Vertical filter (predicts pixel value based on the pixel immediately above).
  • 3: Gradient filter (predicts pixel value using a combination of left, top, and top-left neighbor values: Clip(Left + Top - TopLeft)).

Bits 4–5: Pre-processing

Specifies optional pre-processing applied to the alpha channel to improve compression efficiency:

  • 0: None.
  • 1: Level reduction (quantizes alpha levels to reduce unique symbols).
  • 2–3: Reserved (must be 0).

Bits 6–7: Reserved

These 2 bits are reserved and must be set to 0.

Alpha Bitstream Payload

The remaining bytes of the ALPH chunk contain the alpha values for an image of dimensions \(W \times H\), as defined in the container or VP8 bitstream.

Uncompressed Bitstream (Method 0)

When the compression method is 0, the payload contains raw 8-bit alpha samples in scanline order (row by row, left to right). The payload length equals \(W \times H\) bytes (plus any applied filtering transformations).

Compressed Bitstream (Method 1)

When the compression method is 1, the data is stored using a headless WebP lossless (VP8L) stream:

  • The lossless stream does not contain the standard 5-byte VP8L signature header or dimension fields; dimensions are inferred from the parent image.
  • The 8-bit alpha values are packed into the green channel of the VP8L bitstream, while the other color channels are ignored.
  • The decoder reconstructs the green channel values, inverts any spatial filtering specified in bits 2–3, and maps the resulting data directly to the reconstructed lossy VP8 color canvas.
