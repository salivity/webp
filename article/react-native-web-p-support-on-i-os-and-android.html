React Native WebP Support on iOS and Android

This article provides a comprehensive overview of how React Native handles WebP images on iOS and Android. It covers platform-level decoding capabilities, version requirements, how to handle static versus animated WebP formats, and the recommended tools for achieving consistent cross-platform image rendering.

WebP Support on Android

Android provides native support for WebP images at the operating system level: lossy WebP is supported from Android 4.0 (API 14), and lossless/alpha WebP is supported from Android 4.3 (API 18).

In React Native, Android uses the Fresco image pipeline under the hood. While static WebP images render out of the box on modern React Native releases, handling animated WebP files or ensuring compatibility on older custom builds historically required additional Fresco dependencies. To enable animated WebP playback on Android, you may need to ensure the appropriate Fresco module is included in your android/app/build.gradle:

dependencies {
  // Required for animated WebP support
  implementation 'com.facebook.fresco:animated-webp:2.6.0'
  implementation 'com.facebook.fresco:webpsupport:2.6.0'
}

Most modern React Native versions bundle adequate Fresco modules by default, making static WebP rendering completely seamless.

WebP Support on iOS

Unlike Android, Apple did not natively support WebP through its ImageIO framework until the release of iOS 14. Consequently, WebP handling in React Native on iOS depends heavily on the target OS version and the decoding libraries present in the app.

For devices running iOS 14 and later, the native React Native <Image /> component decodes and renders static WebP files natively without additional pods or manual configurations.

For projects requiring support for older iOS versions, or for projects utilizing animated WebP files (which Apple's native frameworks do not always loop or render reliably), CocoaPods must be configured with an external decoder. Historically, this is handled by adding SDWebImageWebPCoder to your Podfile:

pod 'SDWebImageWebPCoder'

Handling Animated WebP Images

Animated WebP images present distinct challenges across both platforms. React Native's standard <Image /> component is primarily optimized for static assets and basic animated GIFs.

  • Android: Requires the Fresco animated WebP module to play multi-frame WebP assets.
  • iOS: Often treats animated WebP files as single-frame static images unless an external decoding pipeline is explicitly registered.

The Recommended Solution: react-native-fast-image

To avoid platform inconsistencies, caching discrepancies, and configuration overhead, the industry-standard solution for WebP in React Native is using react-native-fast-image.

react-native-fast-image wraps SDWebImage on iOS and Glide on Android. Both underlying libraries provide robust, out-of-the-box support for static and animated WebP, aggressive disk and memory caching, and consistent lifecycle events across both platforms:

import FastImage from 'react-native-fast-image';

const WebPImage = () => (
  <FastImage
    style={{ width: 200, height: 200 }}
    source={{
      uri: 'https://example.com/image.webp',
      priority: FastImage.priority.normal,
    }}
    resizeMode={FastImage.resizeMode.contain}
  />
);

Summary of Platform Handling

  • Static WebP on Android: Fully supported natively via Fresco.
  • Animated WebP on Android: Supported natively or via adding com.facebook.fresco:animated-webp.
  • Static WebP on iOS: Supported natively on iOS 14+ via Apple's ImageIO. Requires third-party coders for earlier iOS versions.
  • Animated WebP on iOS: Best handled via third-party libraries like react-native-fast-image to guarantee consistent playback and looping.
