Native WebP Support in E-Reader Firmware Updates

As the lightweight WebP image format has become a web standard and an official Core Media Type under the EPUB 3.3 specification, dedicated commercial e-reader manufacturers have rolled out firmware updates to support native WebP rendering. This article details the specific firmware releases and software environments across major e-reader brands—including PocketBook, Onyx Boox, Kobo, and Amazon Kindle—that introduced or expanded native playback for WebP images in digital books, standalone documents, and comic archives.

PocketBook: Firmware 6.8 and Beyond

PocketBook was among the first dedicated Linux-based e-reader manufacturers to deploy system-level, native support for WebP.

  • Firmware Version: PocketBook OS 6.8 (and subsequent 6.8.x incremental rollouts).
  • Supported Hardware: PocketBook Era, InkPad 4, InkPad Color 2, Touch Lux 5, and Touch HD 3.
  • Implementation Details: The 6.8 firmware release upgraded the built-in reading engine and gallery viewer. PocketBook added native recognition for WebP files within the operating system's file manager, allowing standalone viewing in the Photo app and native decoding inside EPUB and CBZ/CBR archives without requiring third-party tools like KOReader.

Onyx Boox: Firmware OS 3.3 and OS 3.5

Onyx Boox devices run modified versions of Android, meaning system-level WebP decoding has been theoretically possible for years. However, native reading integration inside the proprietary NeoReader engine required dedicated firmware updates.

  • Firmware Versions: Boox OS 3.3.x through OS 3.5.
  • Supported Hardware: Note Air series, Nova Air, Tab Ultra, Tab Mini C, and Palma.
  • Implementation Details: Prior to OS 3.3, embedded WebP images in EPUB 3 files or CBZ comic containers often caused NeoReader to display broken image placeholders. Onyx updated NeoReader’s core parsing libraries in OS 3.3, followed by a major rendering pipeline overhaul in OS 3.5. These updates enabled hardware-accelerated decoding of both lossy and lossless WebP assets directly inside NeoReader, eliminating the need to install third-party Android viewing apps.

Kobo: Firmware 4.38 and KePub Rendering

Kobo devices use a dual-engine architecture: the standard Adobe Reader Mobile SDK (RMSDK) for traditional EPUBs and a proprietary WebKit-based engine for Kobo EPUBs (KePub).

  • Firmware Version: Kobo Firmware 4.38.21908 (and subsequent 4.38.x/4.39.x builds).
  • Supported Hardware: Kobo Clara 2E, Libra 2, Sage, Elipsa 2E, and earlier compatible hardware.
  • Implementation Details: While legacy RMSDK does not natively process WebP, Kobo updated its internal WebKit-based rendering engine in Firmware 4.38. Because the KePub engine functions similarly to a modernized browser environment, this update enabled seamless native rendering of WebP assets contained within .kepub.epub files. Standalone support remains prioritized for KePub rather than sideloaded, generic EPUB files parsed by the older Adobe stack.

Amazon Kindle: Ingestion Support via Firmware 5.16.x

Amazon does not maintain open format support to the same degree as its competitors, utilizing proprietary formats (AZW3, KFX) rather than native EPUB rendering.

  • Firmware Version: Kindle Firmware 5.16.7 and 5.16.8 (alongside Amazon Cloud Ingestion Updates).
  • Supported Hardware: Kindle Paperwhite (10th & 11th Gen), Kindle Oasis (9th & 10th Gen), Kindle Basic (11th Gen), and Kindle Scribe.
  • Implementation Details: Amazon enabled native WebP support primarily through its delivery pipeline rather than direct on-device decoders for open formats. As part of its transition away from MOBI toward EPUB 3.3 standards, Amazon’s Send to Kindle conversion backend was updated to accept WebP images embedded in EPUBs. When processed, Kindle Firmware 5.16.x correctly displays these images via the updated KFX engine, rendering them as native illustrations without rasterization errors.
