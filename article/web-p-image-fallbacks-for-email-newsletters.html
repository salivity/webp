WebP Image Fallbacks for Email Newsletters

Using WebP images in email campaigns significantly reduces file sizes, leading to faster load times and higher engagement. However, email client support for WebP remains inconsistent, with desktop platforms like Microsoft Outlook and older mobile clients unable to render the format. This guide covers reliable fallback strategies—including the HTML5 <picture> element, Microsoft Outlook conditional comments, and CSS overrides—to guarantee your newsletters display crisp visuals across every inbox without broken image icons.

Why WebP Requires Fallbacks in Email

WebP offers superior lossless and lossy compression compared to traditional PNG and JPEG formats. While modern web browsers and clients like Apple Mail and Gmail (via proxy) support WebP, standalone desktop applications—most notably Microsoft Outlook on Windows (which uses the Microsoft Word rendering engine)—do not. If an email client encounters a WebP image it cannot parse, it displays a broken image icon. Fallbacks ensure that an alternative JPEG or PNG is served whenever WebP compatibility is absent.

Strategy 1: The HTML5 <picture> Element

The most robust method for modern webmail and mobile clients is the HTML5 <picture> tag. This element allows you to define multiple image sources, letting the client pick the first supported format while defaulting to an <img> tag for unsupported environments.

<picture>
  <source srcset="https://example.com/image.webp" type="image/webp">
  <img src="https://example.com/image.jpg" alt="Newsletter Feature" width="600" height="300" style="display: block; width: 100%; max-width: 600px; height: auto;">
</picture>

In this setup, clients that understand the <picture> tag and support WebP will display image.webp. Clients that do not support <picture> or WebP safely ignore the <source> tag and render the standard JPEG defined in the <img> fallback.

Strategy 2: MSO Conditional Comments for Outlook

Microsoft Outlook for Windows does not recognize the HTML5 <picture> tag correctly and may collapse or hide the element entirely. To ensure complete compatibility with Outlook, wrap the <picture> element inside conditional comments that hide it from Outlook, while serving a standard table-based JPEG directly to Microsoft clients.

<!--[if mso]>
<img src="https://example.com/image.jpg" alt="Newsletter Feature" width="600" height="300" border="0" style="display: block;">
<![endif]-->
<!--[if !mso]><!-->
<picture>
  <source srcset="https://example.com/image.webp" type="image/webp">
  <img src="https://example.com/image.jpg" alt="Newsletter Feature" width="600" height="300" style="display: block; width: 100%; max-width: 600px; height: auto;">
</picture>
<!--<![endif]-->

This ensures that Outlook strictly receives a traditional <img> tag pointing to a supported format, eliminating rendering errors completely.

Strategy 3: Progressive Enhancement with CSS Backgrounds

For decorative imagery or hero banners where images are applied via CSS, use progressive enhancement. Set the default background image to a PNG or JPEG, then use CSS classes or media queries to apply the WebP version where supported.

<style>
  .hero-banner {
    background-image: url('https://example.com/hero.jpg');
  }
  @supports (background-image: url('https://example.com/hero.webp')) {
    .hero-banner {
      background-image: url('https://example.com/hero.webp');
    }
  }
</style>

<div class="hero-banner" style="width: 100%; height: 300px; background-size: cover;"></div>

Clients that do not support @supports or WebP will safely display the initial JPEG asset.

Strategy 4: Dynamic CDN Content Negotiation

If altering template code across hundreds of campaigns is impractical, manage fallbacks at the server or CDN level. Content Delivery Networks (CDNs) like Cloudflare, Cloudinary, or Fastly can inspect incoming HTTP request headers—specifically the Accept header.

When an email client requests https://example.com/image.jpg:

  • If the Accept header includes image/webp, the CDN dynamically serves a WebP payload while keeping the file extension identical.
  • If the client does not send WebP compatibility in the header, the CDN delivers the original JPEG or PNG.

Note: Because major services like Gmail route images through an image proxy, the proxy's server headers dictate what is delivered. Gmail's proxy supports WebP, meaning dynamic conversion handles Gmail automatically without additional markup.

Core Best Practices for Implementation

  1. Always Optimize Fallbacks: Do not let standard JPEG/PNG fallbacks bloat your template. Compress fallback files using standard optimization tools so users who do not receive WebP still experience reasonable load times.
  2. Include Fixed Dimensions: Always declare explicit width and height attributes on the fallback <img> tag to prevent layout shifts while the image loads.
  3. Always Include Alt Text: Ensure the underlying <img> element contains descriptive alt text. If image rendering fails or is turned off by user preference, the layout remains informative and accessible.
