Enable WebP Support on Older Android Versions

This article explains how to configure Android applications to load and render WebP image assets across legacy Android versions. While modern Android natively supports WebP, older releases lack full compatibility—particularly for lossless compression, transparency, and animation. By following the configurations outlined below, you can implement third-party decoding libraries and build configurations to ensure WebP assets display reliably across older API levels.

Native Android WebP Compatibility Baseline

Native support for WebP varies significantly by Android API level:

  • Android 4.0 (API 14) to Android 4.1 (API 16): Native support is limited exclusively to lossy WebP images without an alpha channel.
  • Android 4.2.1 (API 17) to Android 8.1 (API 27): Native support added for lossless and transparent (alpha) WebP images.
  • Android 9.0 (API 28)+: Native support added for animated WebP images via ImageDecoder.

If your application targets devices running below API 17, or requires animated WebP playback on devices below API 28, native BitmapFactory decoders will fail or return null.

Configuration 1: Backporting Support via Fresco

The most robust method for rendering WebP on older Android versions is utilizing Facebook's Fresco library. Fresco includes native C++ decoders that bypass the operating system's native limitations.

1. Add Gradle Dependencies

In your module-level build.gradle file, include the core Fresco dependency alongside the specific WebP decoders:

dependencies {
    implementation 'com.facebook.fresco:fresco:3.1.3'

    // For WebP support on Android versions below API 14:
    implementation 'com.facebook.fresco:webpsupport:3.1.3'

    // For animated WebP support on Android versions below API 28:
    implementation 'com.facebook.fresco:animated-webp:3.1.3'
}

2. Initialize the Library

Initialize Fresco inside your custom Application class before loading any views:

public class MyApplication extends Application {
    @Override
    public void onCreate() {
        super.onCreate();
        Fresco.initialize(this);
    }
}

3. Render via SimpleDraweeView

Use Fresco’s custom view in place of standard ImageView components:

<com.facebook.fresco.SimpleDraweeView
    android:id="@+id/webp_image_view"
    android:layout_width="wrap_content"
    android:layout_height="wrap_content"
    fresco:actualImageScaleType="centerCrop" />

Configuration 2: WebP Decoding via Glide

If you use Glide, modern versions automatically handle static WebP on devices running API 17 and above. To add animated WebP support on older versions, integrate a specialized WebP decoder integration.

1. Add the WebP Decoder Library

Add the dependency to your build.gradle file:

dependencies {
    implementation 'com.github.zjupure:webpdecoder:2.6.4.16.0'
    implementation 'com.github.bumptech.glide:glide:4.16.0'
    annotationProcessor 'com.github.bumptech.glide:compiler:4.16.0'
}

2. Configure GlideApp Module

Register the WebP integration module to intercept WebP drawables:

@GlideModule
public class MyAppGlideModule extends AppGlideModule {
    @Override
    public void registerComponents(@NonNull Context context, @NonNull Glide glide, @NonNull Registry registry) {
        // Register WebP decoder to handle animated and static WebP formats
        registry.prepend(InputStream.class, Drawable.class, new ByteBufferWebpDecoder(context));
    }
}

3. Load Assets

Load WebP images from resources or assets directly:

GlideApp.with(context)
    .load("file:///android_asset/sample.webp")
    .into(imageView);

Build Configuration Considerations

When packing WebP assets directly into the res/drawable or assets directories:

  1. AAPT Compression: Ensure AAPT does not alter WebP assets during compilation. Add the following to your module-level build.gradle:

    android {
    aaptOptions {
        noCompress "webp"
    }
}

  2. ABI Architectures: Because libraries like Fresco and custom decoders use native code (libwebp.so) to decode WebP on older OS versions, ensure you include the appropriate native ABIs in your build:

    android {
    defaultConfig {
        ndk {
            abiFilters "armeabi-v7a", "arm64-v8a", "x86", "x86_64"
        }
    }
}
