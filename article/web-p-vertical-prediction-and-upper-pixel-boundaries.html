WebP Vertical Prediction and Upper Pixel Boundaries

Vertical prediction in WebP is a spatial intra-prediction technique derived from the VP8 video format that reduces image file sizes by eliminating vertical redundancy within macroblocks. By taking the reconstructed pixel values from the row immediately above a current macroblock and copying them downward across every row, the encoder creates a baseline estimate of the block's contents. This article explains how WebP accesses these upper boundary pixels, maps them across macroblock columns, and calculates residual data to achieve efficient image compression.

The Role of Intra-Prediction in WebP

WebP divides images into segments known as macroblocks—typically 16x16 pixels for luma (brightness) data, subdivided into 4x4 sub-blocks, along with 8x8 blocks for chroma (color) data. Because images are encoded and decoded sequentially from left to right and top to bottom, adjacent blocks that sit above and to the left of the current target block have already been fully reconstructed.

Intra-prediction exploits this spatial correlation. Rather than storing raw pixel data for every block, WebP predicts what the block looks like based on its decoded borders and encodes only the difference (the residual).

Accessing Upper Boundary Pixels

In vertical prediction mode (labeled as B_VE_PRED in 4x4 blocks or V_PRED in 16x16 macroblocks), the encoder exclusively references the horizontal line of pixels located at \(y = -1\) relative to the top of the current block.

  • For a 16x16 macroblock, the algorithm reads the 16 reconstructed pixels directly touching the top edge.
  • For a 4x4 sub-block, the algorithm reads the 4 reconstructed pixels directly above that specific \(4\times4\) grid.

The pixels to the left, top-left, and top-right are ignored during pure vertical prediction, isolating the top boundary as the sole reference vector.

The Downward Projection Process

Once the upper boundary values are retrieved, the prediction process is straightforward:

  1. Column-Wise Replication: For any column \(x\) within the macroblock (where \(x\) ranges from \(0\) to \(N-1\)), the pixel value at the upper boundary \(P(x, -1)\) is projected straight down.
  2. Uniform Columns: Every pixel in that specific column is assigned the value of the boundary pixel above it: \[\hat{I}(x, y) = P(x, -1)\] for all rows \(y\) from \(0\) to \(N-1\).

If an upper boundary pixel has a brightness value of 180, every pixel in the column beneath it will be predicted as 180. This creates an idealized block composed of vertical stripes or uniform vertical gradients.

Calculating and Compressing Residuals

Real-world image features rarely match the projected boundary pixels perfectly. To preserve visual fidelity, WebP calculates a residual matrix:

\[\text{Residual}(x, y) = \text{Actual}(x, y) - \hat{I}(x, y)\]

  • High Correlation: If the image features vertical structures, stripes, or gradual vertical fades, the predicted values will closely match the real values, driving the residual values toward zero.
  • Frequency Transform: The resulting residual values are converted into frequency space using the Discrete Cosine Transform (DCT). Near-zero residuals translate to high-frequency coefficients of zero, which are aggressively compressed and discarded during quantization without significant visual loss.

Boundary Availability and Fallbacks

Vertical prediction requires a valid reconstructed top boundary. If a macroblock sits at the very top edge of an image (\(y = 0\)), the upper boundary does not exist. In this scenario, vertical prediction cannot be selected by the encoder. WebP will automatically disallow the mode for that block, falling back to modes that rely solely on left boundary pixels (horizontal prediction) or a flat value (DC prediction using default mid-gray values).
