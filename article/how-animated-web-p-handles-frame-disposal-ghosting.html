How Animated WebP Handles Frame Disposal Ghosting

Animated WebP files can suffer from "ghosting" artifacts—unwanted visual remnants or trails from previous frames—when frame disposal and blending parameters are misconfigured during encoding. This article explores the mechanics of WebP animation, explains how the interplay between disposal methods and blending modes influences rendering, identifies why improper configurations cause ghosting on transparent backgrounds, and outlines the solutions required to ensure clean frame transitions.

The Mechanics of Animated WebP Frames

Unlike video formats that refresh the entire screen continuously, animated WebP optimizes file size by updating only the areas of the canvas that change between frames. Each frame in a WebP container consists of a sub-rectangle positioned at specific coordinates \((X, Y)\) with its own width and height.

To render these frames accurately, the WebP specification defines two critical frame-level control flags:

  1. Disposal Method: Instructs the decoder on what to do with the current frame's canvas area after displaying it and before rendering the next frame.
  2. Blend Mode: Instructs the decoder on whether to blend the incoming frame's pixels with the existing canvas pixels using alpha compositing, or to overwrite them completely.

The Cause of Ghosting Artifacts

Ghosting occurs almost exclusively in animations containing transparent or semi-transparent backgrounds.

When an object moves across a transparent canvas, the pixels it previously occupied must either be cleared or replaced. If the encoder fails to clear the moving element's previous position, the new frame is drawn on top of the old frame. Because the new frame contains transparency where the object used to be, the previous frame's pixels remain visible beneath it, creating a smeared, "ghostly" trail of past movements.

This breakdown typically happens when an encoder defaults to keeping the previous frame canvas intact while using alpha blending on subsequent frames, assuming an opaque background exists when it does not.

Frame Disposal Methods in WebP

WebP provides two primary disposal options within its ANMF (Animation Frame) chunk:

  • Do Not Dispose (DISPOSE_DO_NOT): The canvas retains the rendered content of the current frame. The next frame is drawn directly over it. This is ideal for static backgrounds or incremental animations where pixels are added but never subtracted.
  • Dispose to Background (DISPOSE_BACKGROUND): Before rendering the next frame, the area occupied by the current frame is cleared to fully transparent black (rgba(0, 0, 0, 0)). This prevents elements from persisting into the next frame.

If moving transparent graphics use DISPOSE_DO_NOT, ghosting is guaranteed unless the subsequent frame fully covers the exact same area with opaque pixels. Switching to DISPOSE_BACKGROUND forces the decoder to wipe the bounding box of the moving element clean, eliminating visual artifacts.

The Role of Blending Modes

Disposal works in tandem with the blending flag:

  • Blend (BLEND): The incoming frame is composited over the canvas using standard alpha blending (Porter-Duff Over). Transparent areas let the underlying canvas show through.
  • Do Not Blend (NO_BLEND): The incoming frame's pixel values strictly overwrite the corresponding region on the canvas, completely replacing both color and alpha channels without compositing.

Ghosting can be resolved without changing the disposal method if the incoming frame uses NO_BLEND across the entire bounding box that covers the previous position. However, when frames are cropped down to minimal dirty rectangles to save file size, DISPOSE_BACKGROUND paired with proper blending is necessary.

How to Fix and Prevent Ghosting

Resolving ghosting requires proper configuration at the encoding stage:

  • Identify Transparency Requirements: If the asset features transparency, ensure the encoding tool calculates frame differences with awareness of the alpha channel.
  • Configure Encoder Flags: When using standard tools like img2webp or cwebp, ensure frames are not forcefully collapsed with static canvas assumptions. Modern encoders automatically determine whether to use DISPOSE_BACKGROUND or DISPOSE_DO_NOT based on whether pixels in the bounding box become more transparent in the subsequent frame.
  • Full Canvas Clears for Complex Paths: If an optimization tool aggressively trims frame bounding boxes and introduces ghosting, configure the exporter to clear the frame back to the base canvas rather than relying on sub-frame differential rendering.
