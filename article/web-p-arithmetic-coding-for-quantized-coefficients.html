WebP Arithmetic Coding for Quantized Coefficients

WebP employs a boolean arithmetic coder derived from the VP8 video standard to compress quantized transform coefficients into an ultra-compact binary stream. The process involves transforming spatial pixel data using Discrete Cosine Transforms (DCT) or Walsh-Hadamard Transforms (WHT), quantizing the results into discrete integers, and organizing them via zigzag scanning. These quantized coefficients are then mapped into structured discrete tokens using context-adaptive probability trees, which the binary arithmetic coder subsequently packs by continuously narrowing probability intervals to achieve near-optimal entropy limits.

1. Transform and Quantization Setup

Before entropy encoding begins, WebP divides an image into macroblocks and 4x4 sub-blocks. Each sub-block undergoes a discrete transform:

  • Luma/Chroma Blocks: A 4x4 integer Discrete Cosine Transform (DCT) converts spatial pixel residuals into frequency domain coefficients.
  • DC-only Residuals: If a 16x16 macroblock contains a separate DC component, a 4x4 Walsh-Hadamard Transform (WHT) is applied to the DC values.

The resulting frequency values are divided by quantization factors and rounded to the nearest integer. This step introduces lossy compression by zeroing out high-frequency data and reducing the dynamic range of the remaining non-zero values.

2. Scanning and Token Representation

Quantized 4x4 coefficient blocks are flattened into a one-dimensional array of 16 values using a zigzag scan order. This places lower-frequency coefficients, which are more likely to have high energy, near the beginning, and leaves long runs of trailing zeros toward the end.

Instead of encoding raw integer values directly, WebP translates the coefficients into a sequence of predefined tokens:

  • End-of-Block (EOB): Indicates that all remaining coefficients in the 4x4 block are zero.
  • Zero: Encodes an isolated zero coefficient.
  • Small Constants (1–4): Encodes low-magnitude non-zero coefficients directly.
  • Category Bands (5+): Encodes larger magnitudes by combining a category token with literal "extra bits" to define the exact integer value, followed by a single sign bit.

3. Context-Adaptive Probability Trees

The tokens representing the coefficients are structured as decision trees where every node represents a binary choice (0 or 1). WebP determines the probability of taking a left or right branch dynamically using context-adaptive models.

The probability distribution changes depending on:

  • Block Plane: Whether the block belongs to Luma Y1, Luma Y2 (WHT), or Chroma (U/V).
  • Coefficient Position: The specific index (0 to 15) in the zigzag array. Low-frequency indices have different expected value distributions than high-frequency indices.
  • Neighborhood Complexity: The magnitude of the non-zero coefficients immediately preceding the current token, as well as the non-zero state of the adjacent left and top blocks.

WebP maintains a collection of 11 context states for each block type, allowing the arithmetic encoder to select precise, pre-calculated transition probabilities for each branch in the token tree.

4. Binary Arithmetic Encoding Process

Once the context selects the branch probability, the VP8 boolean arithmetic encoder packs the bit into the bitstream:

  1. Interval Subdivision: The encoder maintains an internal state consisting of a 32-bit range (representing the current probability interval) and a value (or low-point register). When encoding a bit with a given probability \(P\), the range is split proportionally: \[\text{split} = 1 + \left(\frac{(\text{range} - 1) \times P}{256}\right)\]
  2. State Transition:
    • If the input bit is 0, the range is truncated to split.
    • If the input bit is 1, the lower bound is shifted upward by split, and the range is reduced to range - split.
  3. Renormalization: As the range shrinks, the top bits of the interval become invariant. The encoder shifts these resolved bits out into the final byte stream and left-shifts the range register until it returns to a valid working size (\(\ge 128\)).

This cycle repeats for every branch of the token tree, for any supplementary literal magnitude bits, and for the sign bits until the entire macroblock of quantized transform coefficients is compressed into the final bitstream.
