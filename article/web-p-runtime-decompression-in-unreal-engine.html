WebP Runtime Decompression in Unreal Engine

Unreal Engine does not natively support runtime decompression of WebP format UI sprites out of the box. While the engine provides a robust asset pipeline that converts standard image formats into engine-optimized GPU textures during the cooking process, it lacks built-in runtime decoders for .webp files within Slate or Unreal Motion Graphics (UMG). Developers seeking to load WebP images dynamically at runtime must rely on custom C++ implementations using third-party libraries like libwebp or third-party Marketplace plugins.

Unreal Engine’s Native Texture Handling

In standard Unreal Engine workflows, UI sprites are imported into the editor as source assets (such as PNG, TGA, or EXR) and compiled into UTexture2D assets. During project packaging (cooking), Unreal Engine compresses these textures into hardware-native formats like BC (Block Compression) for desktop platforms or ASTC/ETC2 for mobile platforms.

Because the GPU natively samples these block-compressed formats, runtime decompression of web formats like WebP is not part of the standard rendering or UI pipeline. The engine expects pre-baked assets that can be streamed directly into GPU memory without CPU-side decompression overhead.

The ImageWrapper Module and WebP

Unreal Engine includes an internal module named IImageWrapper, which handles runtime compression and decompression of select image formats, predominantly:

  • PNG
  • JPEG
  • EXR
  • BMP

WebP is absent from IImageWrapper's standard suite of formats in current vanilla builds of Unreal Engine. Consequently, passing a raw .webp data stream to the default image wrapper interfaces will fail to identify a valid decompression handler.

How to Decompress WebP Sprites at Runtime

To display WebP images fetched dynamically—such as from a remote server or local storage—developers must implement a manual decoding pipeline:

  1. Integrate libwebp: Add Google’s official libwebp C/C++ library as a third-party dependency in your project's Build.cs.
  2. Decode File Bytes: Read the raw byte array of the .webp asset and pass it to WebPDecodeRGBA or WebPDecodeBGRA to obtain raw, uncompressed pixel buffers in memory.
  3. Generate a Dynamic Texture: Call UTexture2D::CreateTransient using the dimensions returned by the decoder, copy the decoded pixel buffer into the texture's platform data, and update the resource (UpdateResource()).
  4. Bind to UI: Wrap the transient UTexture2D inside an FSlateBrush or assign it directly to a UMG UImage widget.

Performance Considerations

Decompressing WebP files at runtime consumes CPU cycles and introduces latency before a sprite can appear on screen. If runtime loading is necessary, WebP decompression should be executed on an asynchronous background thread to avoid hitching the game thread. Once decompressed, the texture resides in system and GPU memory as uncompressed RGBA, consuming significantly more VRAM than native cooked formats like ASTC or BC7. For static UI elements, native engine asset importing remains the recommended approach.
