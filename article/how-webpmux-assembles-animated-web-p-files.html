How webpmux Assembles Animated WebP Files

The webpmux command-line tool, distributed as part of Google’s libwebp package, creates animated WebP files by multiplexing individual static WebP images into an extended RIFF container. This article explains how webpmux processes input frames, configures animation chunks, and defines parameters such as frame duration, positioning, disposal, and blending to produce a fully functional animated image.

The WebP Container Structure

A standard, static WebP image often uses a simple Resource Interchange File Format (RIFF) container wrapping raw VP8 or VP8L (lossless) bitstream data. When handling animations, webpmux elevates the file to the Extended WebP file format, signaled by a VP8X header chunk.

This extended header sets flags indicating that the file contains animation data, canvas dimensions, and metadata. Within this format, webpmux injects two critical chunk types to govern playback:

  • ANIM Chunk: Stores global animation parameters, such as the default canvas background color and the global loop count (where 0 denotes infinite looping).
  • ANMF Chunk: Precedes every individual frame in the animation sequence, storing frame-specific layout and behavior instructions alongside the frame’s image payload.

The Assembly Syntax

webpmux accepts an ordered sequence of frames through the -frame flag. The syntax specifies how each image is rendered onto the main canvas:

webpmux -frame frame1.webp +di+xi+yi+mi+bi ... -loop c -bgcolor A,R,G,B -o output.webp

The parameters appended to each frame define its temporal and spatial behavior:

  • Duration (+di): The display time of the frame in milliseconds.
  • Offset coordinates (+xi+yi): The horizontal and vertical starting positions of the frame on the global canvas. This allows individual frames to be smaller than the overall canvas, updating only the region of the image that changes.
  • Disposal method (+mi): Dictates how the canvas area occupied by the frame is treated before rendering the next frame. A value of 0 leaves the frame in place, while 1 resets the frame's area back to the background color.
  • Blending method (+bi): Governs alpha transparency interaction. A value of +b blends the new frame with the existing canvas pixels using alpha compositing, whereas -b overwrites the destination pixels entirely without blending.

Step-by-Step Multiplexing Process

  1. Reading Input Bitstreams: webpmux reads each supplied static WebP file, verifies its integrity, and extracts the core image data (lossy VP8, lossless VP8L, or alpha chunks).
  2. Global Canvas Allocation: Based on the frame dimensions, offsets, or explicit container sizes, the tool calculates the total canvas width and height, writing these values to the VP8X chunk.
  3. Generating Frame Payloads: For every frame input, webpmux constructs an ANMF chunk. It writes the frame’s duration, coordinates, disposal mode, and blending mode into the chunk's 16-byte metadata header, followed immediately by the raw WebP image bitstream.
  4. Serialization: webpmux packages the RIFF header, the VP8X chunk, the ANIM chunk, and the series of ANMF chunks into a single binary stream, updating all internal chunk sizes and padding bytes to ensure 2-byte alignment as required by the RIFF standard.

Through this structural packaging, webpmux allows developers to assemble animations efficiently by reusing compressed image bitstreams without needing to re-encode each frame from scratch.
