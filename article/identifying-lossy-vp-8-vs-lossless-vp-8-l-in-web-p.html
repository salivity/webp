Identifying Lossy VP8 vs Lossless VP8L in WebP

A WebP parser determines whether an image contains lossy VP8 or lossless VP8L data by reading the Four-Character Codes (FourCC) embedded within the file’s Resource Interchange File Format (RIFF) container. Depending on whether the file uses a simple or extended container format, the parser identifies specific chunk tags—specifically "VP8 " for lossy compression and "VP8L" for lossless compression—to route the payload to the correct decompression engine.

The RIFF Container Basics

Every standard WebP file begins with a 12-byte header:

  1. Bytes 0–3: The ASCII string "RIFF".
  2. Bytes 4–7: A 32-bit little-endian integer indicating the file size (minus 8 bytes).
  3. Bytes 8–11: The ASCII string "WEBP".

Immediately following byte 11, the file contains sequential data chunks. Each chunk consists of a 4-byte FourCC identifier, a 4-byte little-endian payload size, and the actual payload. A WebP parser inspects this initial FourCC identifier to determine the file type.

Simple Lossy WebP (VP8 )

In a simple lossy file, the chunk header immediately following the "WEBP" signature is "VP8 " (with an ASCII space character at the end, represented in hex as 0x56 0x50 0x38 0x20).

When a parser encounters "VP8 ":

  • It recognizes that the payload is an encoded VP8 keyframe (derived from the VP8 video codec standard).
  • It verifies the 10-byte VP8 frame header within the payload, checking for the 3-byte frame tag and the start code 0x9D 0x01 0x2A.
  • It routes the subsequent data to the lossy VP8 decoder.

Simple Lossless WebP (VP8L)

In a simple lossless file, the chunk header immediately following the "WEBP" signature is "VP8L" (hex: 0x56 0x50 0x38 0x4C).

When a parser encounters "VP8L":

  • It identifies the stream as proprietary WebP lossless data, which uses spatial transform techniques, color transforms, entropy coding, and LZ77-based back-referencing.
  • It verifies the stream’s 1-byte signature at the start of the payload, which must equal 0x2F.
  • It routes the payload directly to the VP8L decoder.

Extended WebP Files (VP8X)

If the WebP file contains advanced features—such as transparency in lossy images, animation, metadata (EXIF/XMP), or an ICC color profile—the first chunk identifier is "VP8X" (hex: 0x56 0x50 0x38 0x58).

When an extended header is present, the parser cannot determine the compression type from the very first chunk. Instead, it follows this process:

  1. Read the VP8X Chunk: The parser reads the 10-byte VP8X payload, which includes flags indicating features like the presence of an alpha channel, animation, or metadata, followed by the canvas width and height.
  2. Iterate Through Remaining Chunks: The parser walks through the subsequent chunks in the container:
    • For Still Images: The parser continues reading until it encounters either a "VP8 " chunk (lossy data) or a "VP8L" chunk (lossless data). If the image is lossy with transparency, the parser will also encounter an "ALPH" chunk before the "VP8 " chunk, which contains the alpha map encoded using lossy or lossless compression. If the image is lossless, alpha is handled directly inside the "VP8L" data stream.
    • For Animated Images: The parser encounters an "ANIM" chunk followed by multiple "ANMF" (animation frame) chunks. Each "ANMF" chunk wraps the data for an individual frame, which internally contains its own "VP8 " or "VP8L" sub-chunk, allowing an animated file to mix lossy and lossless frames.

By checking for "VP8 " or "VP8L" tags either at byte 12 (simple files) or deeper in the chunk stream (extended VP8X files), the parser conclusively identifies the compression format.
