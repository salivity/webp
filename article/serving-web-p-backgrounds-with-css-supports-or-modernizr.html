Serving WebP Backgrounds with CSS @supports or Modernizr

Serving modern, lightweight WebP background images significantly improves webpage performance, but ensuring compatibility for environments that do not support the format requires a solid fallback strategy. While developers frequently turn to native CSS @supports rules or JavaScript-based Modernizr classes to handle this conditionally, each approach functions differently under the hood. This guide examines how both methods work to deliver WebP background images dynamically, highlighting their strengths, limitations, and practical implementation.

The Limitation of Basic CSS @supports

A common misconception is that you can test WebP support using a straightforward CSS declaration such as:

@supports (background-image: url("test.webp")) {
  .hero {
    background-image: url("test.webp");
  }
}

This approach does not work as expected. The CSS @supports rule checks whether a browser parses the CSS syntax of a property and value, not whether the browser's rendering engine can decode the underlying image format. Because url("test.webp") is syntactically valid CSS in every modern browser, the rule evaluates to true even on browsers that cannot render WebP, breaking the fallback.

Serving WebP via CSS image-set()

To conditionally load WebP backgrounds using pure CSS, you must use the image-set() function within background-image. The image-set() function allows you to specify the MIME type of an image, which browsers do evaluate before downloading:

.hero {
  /* Fallback for legacy browsers */
  background-image: url("hero.jpg");
  
  /* Modern browsers negotiate the format */
  background-image: image-set(
    url("hero.webp") type("image/webp"),
    url("hero.jpg") type("image/jpeg")
  );
}

If a browser supports image-set() and the WebP format, it downloads the WebP version. If it does not support WebP, it defaults to the JPEG alternative. You can wrap this in an @supports (background-image: image-set(...)) query if you need to isolate styles strictly for supporting browsers.

Serving WebP Using Modernizr

Modernizr resolves the detection problem via client-side JavaScript. Instead of relying on CSS syntax parsing, Modernizr actively attempts to decode a base64-encoded WebP image in the browser.

Upon completion of the test, Modernizr appends either a webp or no-webp class to the root <html> element. This enables precise styling directly through standard CSS cascading:

/* Default fallback */
.hero {
  background-image: url("hero.jpg");
}

/* Applied only if WebP decode succeeds */
html.webp .hero {
  background-image: url("hero.webp");
}

This method is reliable across legacy browsers because it confirms actual decoding capabilities before applying the rule. However, it requires an external JavaScript execution step before the final background image can be requested, which can marginally delay the resource download compared to native CSS parsing.

Which Approach Should You Use?

Modern browser support for WebP is virtually universal across all current major platforms, including modern versions of Chrome, Firefox, Safari, and Edge.

  • Use CSS image-set() if your target audience uses modern browsers and you want a zero-JavaScript, non-render-blocking solution.
  • Use Modernizr if you must support older legacy browsers (such as Internet Explorer 11 or older Safari releases on macOS/iOS) where format negotiation is not supported natively via CSS.
