How Horizontal Prediction Works in WebP Lossy Coding

Horizontal prediction in WebP lossy compression is an intra-frame prediction mode that reduces spatial redundancy by projecting pixel values from the left adjacent boundary across entire rows of a block. Inherited from the VP8 video codec, this technique models horizontal color consistency, allowing the encoder to transmit only the differences between the predicted values and the actual image data. By analyzing the pixel immediately to the left of each row, the algorithm provides an efficient baseline that captures vertical gradients while compressing horizontally continuous visual elements.

The Mechanism of Horizontal Prediction

WebP divides images into macroblocks, typically processing luma components in 16x16 or 4x4 sub-blocks, and chroma components in 8x8 blocks. Lossy WebP reconstructs images sequentially from left to right and top to bottom. Because of this processing order, when an encoder evaluates a given block, the block directly to its left has already been reconstructed.

The horizontal prediction mode (designated as H_PRED in VP8/WebP) operates using the single vertical column of reconstructed pixels immediately bordering the left edge of the target block.

For a block of size \(N \times N\), the process follows these steps:

  1. Reference Acquisition: The encoder reads the column vector of reconstructed boundary pixels \(L\), where \(L(y)\) represents the pixel directly to the left of row \(y\) (for \(y = 0\) to \(N - 1\)).
  2. Row-Wise Extrapolation: For each row \(y\) within the block, the value of \(L(y)\) is replicated across every horizontal position \(x\) (for \(x = 0\) to \(N - 1\)).
  3. Prediction Matrix Generation: The predicted value \(\hat{P}(x, y)\) for any pixel in the block is defined strictly by its row index: \[\hat{P}(x, y) = L(y)\]

Operation on Adjacent Pixel Rows

Because the prediction relies entirely on the left boundary pixel of each respective row, adjacent rows inside the block operate independently of one another horizontally, but collectively preserve vertical changes:

  • Row Independence: Row \(y\) uses \(L(y)\) as its predictor for all \(x\), while the adjacent row \(y+1\) uses \(L(y+1)\). There is no horizontal blending or cross-talk between row \(y\) and row \(y+1\) during the prediction phase.
  • Preservation of Vertical Gradients: If the source image contains a vertical color ramp or distinct horizontal stripes, \(L(y)\) and \(L(y+1)\) will differ. Horizontal prediction carries these differences across the entire width of the block, naturally modeling horizontal edges and vertical gradients without requiring high-frequency residual data.
  • Handling Smooth Transitions: In regions with flat horizontal textures, the difference between the actual pixel values in a row and the predictor \(L(y)\) remains close to zero.

Residual Calculation and Transform

Once the horizontal predictor block \(\hat{P}\) is generated, the encoder computes the residual matrix \(R\):

\[R(x, y) = P(x, y) - \hat{P}(x, y)\]

where \(P(x, y)\) is the original pixel value.

If the image region consists of horizontal lines, bands, or uniform colors extending from the left, the residual values \(R(x, y)\) across adjacent rows will be near zero. This residual matrix is then converted via a Discrete Cosine Transform (DCT), quantized, and entropy-coded. When horizontal prediction is selected effectively, the DCT yields mostly zero-value coefficients, achieving high compression ratios while retaining sharp horizontal features.
