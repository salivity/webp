Capture Full-Page WebP Screenshots in Puppeteer

This article explains how headless browsers like Puppeteer capture and encode full-page screenshots directly into the WebP format. It covers the internal communication with the Chrome DevTools Protocol (CDP), how the browser measures total document dimensions, the rendering and rasterization process, and how Chromium encodes the raw pixel buffer into a lightweight WebP file.

The Chrome DevTools Protocol (CDP)

Puppeteer is a Node.js library that controls Chromium-based browsers over the Chrome DevTools Protocol (CDP). When you instruct Puppeteer to take a screenshot, it does not use operating system capture tools. Instead, it sends low-level commands via WebSockets directly to Chromium's internal rendering engine.

The core command responsible for screenshots is Page.captureScreenshot. Puppeteer translates high-level API options into this command's parameters, including visual clipping, image compression formats, and quality settings.

Calculating the Full-Page Dimensions

A standard browser window only renders what fits inside its current viewport. To capture a "full-page" screenshot, Puppeteer and Chromium execute the following steps:

  1. Query Layout Metrics: Puppeteer sends the Page.getLayoutMetrics command to CDP. This retrieves the total dimensions of the scrollable content (contentSize), accounting for the total width and height of the HTML document.
  2. Emulate Device Metrics: Puppeteer uses Emulation.setDeviceMetricsOverride to resize the browser's viewport temporarily to match the exact width and height of the full document.
  3. Trigger Reflow and Paint: Changing the viewport forces the browser's layout engine (Blink) to recalculate styles, reflow the DOM, and paint elements that were previously outside the visible screen.
  4. Restore Defaults: After capturing the image data, Puppeteer resets the viewport back to its initial dimensions to prevent persistent layout disruption.

Rasterization and WebP Encoding

Once the layout covers the entire page dimensions, Chromium captures the rendered output:

  1. Compositing and Rasterization: Chromium uses its graphics engine, Skia, to rasterize the DOM, styles, and images into raw pixel buffers (bitmaps) stored in memory.
  2. Native WebP Conversion: Chromium contains a built-in WebP encoder powered by the open-source libwebp library. When the type parameter is set to webp, Chromium pipes the raw bitmap data directly to this encoder inside the browser process.
  3. Compression: If specified, the quality parameter (ranging from 0 to 100) dictates the lossy compression level applied by libwebp. If no quality is specified, Chromium uses its default lossy compression profile.
  4. Buffer Transfer: Chromium encodes the image and converts it into a Base64-encoded string, which is transmitted back to Puppeteer over the CDP connection. Puppeteer decodes this string into a Node.js Buffer and writes it to the specified file path.

Implementation Example

The entire sequence is executed using a single method call in Puppeteer:

const puppeteer = require('puppeteer');

(async () => {
  const browser = await puppeteer.launch();
  const page = await browser.newPage();

  await page.goto('https://example.com', { waitUntil: 'networkidle0' });

  await page.screenshot({
    path: 'fullpage.webp',
    type: 'webp',
    quality: 80,
    fullPage: true
  });

  await browser.close();
})();

Advantages of Native WebP Capture

Using native WebP capture provides significant performance advantages over traditional PNG or JPEG workflows. Because the compression happens internally within Chromium's C++ codebase before the data is transmitted to Node.js, it minimizes memory overhead and eliminates the need for external image processing libraries like Sharp or ImageMagick. Additionally, WebP offers superior compression ratios, substantially reducing the storage footprint of large, full-page visual captures.
