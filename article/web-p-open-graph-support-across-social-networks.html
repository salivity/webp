WebP Open Graph Support Across Social Networks

While modern web browsers universally support the lightweight WebP image format, social media link scrapers and preview generators do not share the same consistency. Specifying a WebP file in your Open Graph metadata (og:image) often leads to broken previews, missing thumbnails, or fallback errors across several platforms. Despite WebP being an established standard for over a decade, key networks—most notably LinkedIn, Pinterest, and messaging platforms like WhatsApp—still exhibit partial, unreliable, or nonexistent support for WebP social cards.

Platforms That Fail or Struggle with WebP Open Graph Images

LinkedIn

LinkedIn remains the most prominent platform that reliably fails to render WebP images defined in og:image tags. The LinkedIn Post Inspector and feed generator typically ignore WebP assets entirely, causing the shared link to display as a bare text card without a thumbnail. LinkedIn's developer documentation specifies support strictly for PNG and JPEG formats for rich link previews.

WhatsApp

Although WhatsApp natively uses WebP for its sticker ecosystem, its link preview crawler operates through a different pipeline. When generating previews for links shared in chats, WhatsApp frequently fails to parse WebP metadata images. This results in either an empty preview box or a low-resolution site favicon instead of the intended featured image. For consistent card generation, WhatsApp's preview parser requires JPEG or PNG assets under 300 KB.

Pinterest

Pinterest relies heavily on rich visual metadata to generate Rich Pins. While Pinterest has improved its ability to crawl images directly embedded on webpages, its Open Graph metadata parser often drops or fails to process WebP images linked in the page header. This leads to broken pin creation or prompts the user to manually select an alternative image from the page body.

Skype and Microsoft Teams

Enterprise communication tools powered by Microsoft's link-unfurling engines display inconsistent behavior with WebP cards. Skype frequently strips WebP previews completely, while Microsoft Teams occasionally fails to generate cached thumbnails from WebP sources, defaulting to basic text snippets.

Platforms That Successfully Support WebP

  • Facebook: Meta's crawler supports standard, static WebP images. However, animated WebP files are not supported and will either fail or display only the first frame.
  • X (formerly Twitter): The Twitter Card validator and feed parser support static WebP images alongside PNG, JPEG, and GIF.
  • Discord: Discord uses modern media proxies that reliably fetch, convert, and display WebP assets in embed previews.
  • Telegram: Telegram's preview bot seamlessly renders WebP metadata images across mobile and desktop clients.

Recommended Implementation Strategy

Because social scrapers do not behave like modern web browsers, using content negotiation or automated WebP replacement across the entire document can harm your social distribution. The most reliable implementation involves:

  1. Retaining JPEG or PNG for Social Metadata: Keep the target of og:image and twitter:image tags pointed to an optimized JPEG or PNG file (ideally 1200x630 pixels).
  2. Serving WebP to Real Users: Serve WebP or AVIF formats for the visible content within the HTML body using the <picture> element or CSS.
  3. User-Agent Detection (Edge Caching): If serving dynamic assets via a CDN, configure edge rules to serve JPEG fallbacks specifically to user-agents containing known crawler strings (such as LinkedInBot, WhatsApp, or Pinterestbot).
