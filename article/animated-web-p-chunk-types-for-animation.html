Animated WebP Chunk Types for Animation

Animated WebP files use the Resource Interchange File Format (RIFF) container to structure image and metadata into distinct data blocks called chunks. Inside an animated WebP file, playback behavior, loop rules, and individual frame sequences are defined by three key chunk types: VP8X, ANIM, and ANMF. This article breaks down each of these chunk types and explains how they work together to control and display animation sequences.

The VP8X Chunk (Extended File Format)

Before any animation data is read, the file must include an extended header chunk known as VP8X. This chunk signals to decoders that the file uses advanced features beyond a basic lossy or lossless still image.

Within the VP8X chunk, a specific bit flag—the Animation flag (bit 1)—is set to 1. This instructs the parser to expect animation control data and individual animation frames rather than treating the file as a single static image. The VP8X chunk also defines the canvas width and height for the entire animation.

The ANIM Chunk (Animation Control)

The ANIM chunk defines global parameters for the animation sequence as a whole. It appears once in the file, preceding the frame data, and consists of two primary parameters:

  • Background Color (32 bits): Specifies the default canvas background color in [Blue, Green, Red, Alpha] byte order. This color is shown on unused areas of the canvas or when a frame's disposal method clears to the background.
  • Loop Count (16 bits): Defines how many times the animation should loop. A value of 0 denotes infinite looping, while any other integer dictates the exact number of playback repetitions.

The ANMF Chunk (Animation Frame)

The ANMF chunk is the core component that defines individual frames within an animation sequence. An animated WebP file contains an ordered sequence of multiple ANMF chunks, where each chunk represents a single step in the animation timeline.

Each ANMF chunk contains both control metadata and the raw image data payload for that specific frame:

  • Frame X and Frame Y Offsets (24 bits each): The horizontal and vertical coordinates where the top-left corner of the frame should be placed relative to the main canvas.
  • Frame Width and Frame Height (24 bits each): The dimensions of the frame itself, which can be smaller than the overall canvas to optimize file size by updating only altered regions.
  • Frame Duration (24 bits): The display time for the current frame, measured in milliseconds.
  • Flags (8 bits):
    • Blending Method: Indicates whether transparent pixels of the current frame should be blended with the corresponding pixels of the previous canvas state, or if the current frame should overwrite the previous state entirely.
    • Disposal Method: Determines what to do with the frame's canvas area after it is displayed. It can either retain the frame's pixels on the canvas or dispose of the area by reverting it back to the background color defined in the ANIM chunk.
  • Frame Bitstream Data: The sub-chunks containing the actual pixel data for the frame. This payload can consist of standard lossy VP8 data, lossless VP8L data, or an optional ALPH (Alpha) chunk preceding a lossy VP8 chunk.
