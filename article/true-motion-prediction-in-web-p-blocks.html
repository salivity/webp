TrueMotion Prediction in WebP Blocks

TrueMotion prediction is a specialized spatial intra-prediction mode used in the WebP image format to reconstruct smooth gradients across pixel blocks. Inherited from the VP8 video codec, this prediction mode uses reconstructed boundary pixels from adjacent blocks to predict interior values. This article explains how TrueMotion prediction utilizes the top-left corner pixel to calculate directional variances and generate continuous interior pixel approximations within WebP macroblocks.

The Boundary Reference Framework

When predicting an \(4\times4\) or \(16\times16\) luma or chroma block using TrueMotion, the decoder relies on three sets of previously decoded boundary pixels:

  • Above Row (\(A\)): The row of reconstructed pixels directly above the current block (\(A[x]\), where \(x\) represents the column index).
  • Left Column (\(L\)): The column of reconstructed pixels immediately to the left of the current block (\(L[y]\), where \(y\) represents the row index).
  • Top-Left Corner (\(C\)): The single pixel located diagonally above and to the left of the block's origin, positioned at relative coordinates \((-1, -1)\).

The TrueMotion Formula

The core mechanic of TrueMotion prediction relies on a simple arithmetic formula that projects both horizontal and vertical variations across the block. The predicted value \(\hat{P}(x, y)\) for any pixel located at coordinate \((x, y)\) inside the block is calculated as:

\[\hat{P}(x, y) = \text{Clip1}(L[y] + A[x] - C)\]

Where:

  • \(L[y]\) is the neighbor pixel in the same row.
  • \(A[x]\) is the neighbor pixel in the same column.
  • \(C\) is the top-left corner neighbor pixel.
  • \(\text{Clip1}(\cdot)\) clamps the output to the valid 8-bit pixel range of \([0, 255]\) to prevent underflow or overflow.

How Corner Pixel Variance Is Factored

The top-left corner pixel (\(C\)) functions as a baseline offset. Rather than treating the horizontal and vertical projections independently, TrueMotion evaluates the delta between the boundary pixels and this common origin point.

The formula can be mathematically rearranged to highlight how local variances are computed:

\[\hat{P}(x, y) = L[y] + (A[x] - C)\]

or conversely:

\[\hat{P}(x, y) = A[x] + (L[y] - C)\]

In this structure:

  1. Horizontal Delta: The term \((A[x] - C)\) calculates the local variance along the top edge relative to the corner. This differential captures whether the intensity is increasing or decreasing along the horizontal axis.
  2. Vertical Delta: The term \((L[y] - C)\) calculates the local variance along the left edge relative to the corner, capturing the vertical gradient.
  3. Compound Reconstruction: When adding the horizontal variance \((A[x] - C)\) to the current left pixel \(L[y]\), the algorithm carries the horizontal slope down through the entire block while anchoring it to the vertical baseline established by \(L[y]\).

Dynamic Range and Clipping

Because combining two boundary values and subtracting a corner pixel can yield values outside the valid unsigned 8-bit integer range, clamping is essential:

\[\text{Clip1}(v) = \begin{cases} 0 & \text{if } v < 0 \\ 255 & \text{if } v > 255 \\ v & \text{otherwise} \end{cases}\]

For instance, if \(L[y] = 200\), \(A[x] = 210\), and \(C = 50\), the unclipped variance yields:

\[200 + 210 - 50 = 360\]

The clamping operation restricts this result to \(255\), ensuring the pixel remains within valid boundaries while preserving the directional trend as closely as possible.

Spatial Efficiency in WebP

By using the corner pixel as an anchor to subtract redundant baseline luminance, TrueMotion accounts for simultaneous horizontal and vertical shifts. This makes it significantly more accurate than pure horizontal or pure vertical prediction modes when compressing blocks containing soft lighting, vignettes, or diagonal gradients. Consequently, the residual error passed to the discrete cosine transform (DCT) stage is minimized, reducing the file size required to encode the block.
