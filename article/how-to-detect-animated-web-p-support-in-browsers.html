How to Detect Animated WebP Support in Browsers

Detecting browser support for animated WebP is essential for serving performant, high-quality animations without breaking user experiences on older clients. Because support for static WebP images does not guarantee support for the animated format, developers cannot rely on generic image tests. This article explains the limitations of CSS feature queries regarding image codec detection, how Modernizr handles animated WebP detection asynchronously, and how to implement a lightweight, native JavaScript test to verify animated WebP capabilities.

The Limitation of CSS Feature Queries

Native CSS feature queries (@supports) cannot detect specific image codecs or sub-formats like animated WebP. The @supports rule is designed to evaluate whether a browser parses and understands specific CSS property-value pairs (such as @supports (display: grid)), not whether the underlying rendering engine can successfully decode a specific image container format.

Attempting to test image support using syntax like @supports (background-image: url("test.webp")) will always evaluate to true in modern browsers because the url() syntax itself is valid, regardless of whether the browser can decode the target file. Consequently, animated WebP detection must be handled through JavaScript-driven feature detection rather than pure CSS.

Detecting Animated WebP with Modernizr

Modernizr tests image format support by attempting to decode actual minimal image files encoded as base64 data URIs. Because image decoding is an asynchronous process, Modernizr's WebP tests are asynchronous and grouped under sub-features.

To test specifically for animated WebP using Modernizr:

  1. Build a custom Modernizr package that includes the webp.animation feature detect.
  2. Listen for the detection result using Modernizr’s asynchronous event handler:
Modernizr.on('webpanimation', function(result) {
  if (result) {
    // Browser supports animated WebP
    document.documentElement.classList.add('webp-animation');
  } else {
    // Browser does not support animated WebP
    document.documentElement.classList.add('no-webp-animation');
  }
});

Modernizr injects a two-frame animated WebP data URI into an in-memory Image object. If the image successfully triggers an onload event and exhibits dimensions matching the test payload, the webpanimation flag resolves to true.

Native JavaScript Feature Detection

If you do not want to load the entire Modernizr library, you can replicate the exact detection mechanism using a standalone JavaScript function. The following implementation uses a minimal base64-encoded animated WebP image (a 1x1 pixel file containing two frames) and returns a Promise:

function checkAnimatedWebPSupport() {
  return new Promise((resolve) => {
    // Minimal 1x1 pixel animated WebP data URI
    const animatedWebPData = 'data:image/webp;base64,UklGRlIAAABXRUJQVlA4WAoAAAASAAAAAAAAAAAAQU5JTQYAAAD/////AABBTk1GJgAAAAAAAAAAAAAAAAAAAGQAAABWUD4yAAAACAMAnQEqAQABAAEAiUlpsAC4A34AAP7/twAAAA==';

    const image = new Image();
    
    image.onload = function () {
      // Check if image decoded successfully and has correct dimensions
      const hasSupport = image.width > 0 && image.height > 0;
      resolve(hasSupport);
    };

    image.onerror = function () {
      resolve(false);
    };

    image.src = animatedWebPData;
  });
}

Implementing the Detection Result

Once the Promise resolves, you can update the DOM to enable CSS-based fallbacks or conditionally serve media formats in your application:

checkAnimatedWebPSupport().then((isSupported) => {
  if (isSupported) {
    document.documentElement.classList.add('webp-anim');
  } else {
    document.documentElement.classList.add('no-webp-anim');
  }
});

With this class in place, you can safely configure CSS background fallbacks to serve animated GIFs or APNG files to unsupported browsers while delivering smaller animated WebP files to modern environments:

.hero-animation {
  background-image: url('animation.gif');
}

.webp-anim .hero-animation {
  background-image: url('animation.webp');
}

For inline content, you can bypass JavaScript detection entirely by using the HTML <picture> element with appropriate MIME types, allowing the browser engine to handle selection natively:

<picture>
  <source srcset="animation.webp" type="image/webp">
  <img src="animation.gif" alt="Animated illustration">
</picture>
