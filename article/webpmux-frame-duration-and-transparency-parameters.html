Webpmux Frame Duration and Transparency Parameters

This guide explains how to configure individual frame durations and transparency behaviors in animated WebP files using Google's webpmux command-line utility. By leveraging specific arguments inside the -frame flag, you can customize frame timing in milliseconds, specify whether previous frame data is preserved or cleared, and control alpha blending modes for accurate transparent rendering.

The -frame Syntax Structure

In webpmux, all frame-level playback and visual properties are set sequentially through the -frame option. The full parameter syntax for each frame is:

-frame file_name +x_offset+y_offset+duration+dispose_method+blend_method

The parameters controlling duration, canvas clearing, and alpha transparency are duration, dispose_method, and blend_method.

Controlling Frame Duration

Frame duration is controlled by the third argument following the offsets:

  • Parameter: +duration
  • Format: An integer representing time in milliseconds (ms).
  • Behavior: A value of +100 displays the frame for 100ms (10 frames per second), while +40 displays it for 40ms (25 frames per second). Each frame added to the sequence can possess an independent duration value to create variable frame rate animations.

Controlling Transparency and Disposal Modes

Two distinct parameters govern how transparent pixels and frame transitions interact on the canvas: dispose_method and blend_method.

1. Disposal Method (dispose_method)

The disposal method specifies how the canvas area occupied by the current frame is treated after its duration expires, before the next frame is rendered. This is crucial for animations with transparent backgrounds.

  • +b (Do Not Dispose / None): Preserves the current frame on the canvas. The next frame renders directly on top of the existing content.
  • +d (Dispose to Background): Clears the rectangular area of the current frame back to the background color (fully transparent by default) before drawing the next frame. This prevents "ghosting" artifacts where transparent areas of a new frame accidentally reveal parts of previous frames.

2. Blend Method (blend_method)

The blend method dictates how the current frame's transparent and semi-transparent pixels interact with the pixels already present on the canvas.

  • +m (Alpha Blend): Blends the new frame with the canvas beneath it using standard alpha compositing. Semi-transparent pixels will show the underlying frame's colors through them.
  • -m (Do Not Blend): Overwrites the destination canvas completely within the frame boundary. Transparent or semi-transparent pixels in the new frame will completely replace whatever was on the canvas rather than mixing with it.

Example Command

The following command assembles two frames where frame1.webp displays for 200ms without disposal, and frame2.webp displays for 500ms, clears the background upon completion, and renders without alpha blending:

webpmux -frame frame1.webp +0+0+200+b+m \
        -frame frame2.webp +0+0+500+d-m \
        -loop 0 -bgcolor 0x00000000 -o output.webp

In this command, +200+b+m sets a 200ms duration, retains the image content (+b), and enables alpha blending (+m). The second frame uses +500+d-m to display for 500ms, clear to transparent background on completion (+d), and overwrite existing canvas pixels without alpha blending (-m).
