Serve Cached WebP Images in Nginx with try_files

This guide explains how to configure Nginx to automatically deliver pre-generated, cached WebP images in place of standard JPEG and PNG files using the try_files directive. By inspecting the browser's Accept header and matching requested file paths against existing .webp copies, Nginx can deliver smaller image payloads with minimal latency and provide an automatic fallback to the original format when WebP is unsupported or the cached file is missing.

1. Detect WebP Support with the map Directive

Add a map block inside the http context of your Nginx configuration (typically /etc/nginx/nginx.conf). This block evaluates the client's Accept header and sets a custom variable $webp_suffix to .webp if the client supports the format.

http {
    # Other configuration settings...

    map $http_accept $webp_suffix {
        default "";
        "~*image/webp" ".webp";
    }
}

If the client sends a header including image/webp, $webp_suffix is populated with .webp. If not, it remains an empty string.

2. Configure the location Block Using try_files

Inside your server block (such as in your site configuration under /etc/nginx/conf.d/ or /etc/nginx/sites-available/), define a location block matching your target image extensions. Use try_files to verify the presence of the cached .webp version.

server {
    # Other server configurations...

    location ~* \.(png|jpe?g)$ {
        add_header Vary Accept;
        try_files $uri$webp_suffix $uri =404;
    }
}

How It Works

  1. Vary Header: The add_header Vary Accept; directive instructs CDNs and intermediate caches to store distinct versions of the image depending on whether the requesting client supports WebP.
  2. First Check ($uri$webp_suffix): If the client supports WebP, this resolves to /path/to/image.jpg.webp. If that file exists on the server disk or cache directory, Nginx immediately serves it. If the client does not support WebP, $webp_suffix is empty, so this directly matches the original file.
  3. Fallback Check ($uri): If the WebP copy does not exist, Nginx falls back to checking the original path /path/to/image.jpg.
  4. Final Fallback (=404): If neither the WebP variant nor the original file exists, Nginx returns a 404 Not Found error.

3. Ensure Proper MIME Types

Verify that your Nginx setup properly assigns the image/webp MIME type. Open /etc/nginx/mime.types and verify that the following line exists:

image/webp webp;

Because try_files resolves directly to the .webp file extension when served, Nginx will automatically serve the file with the Content-Type: image/webp header.

4. Test and Reload Nginx

Validate the configuration files for syntax errors before applying the changes:

nginx -t

If the test passes, reload Nginx to activate the new configuration:

systemctl reload nginx
