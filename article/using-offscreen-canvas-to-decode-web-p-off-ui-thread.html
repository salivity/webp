Using OffscreenCanvas to Decode WebP Off UI Thread

Modern web browsers fully support decoding and manipulating WebP image data off the main UI thread using OffscreenCanvas combined with Web Workers and the createImageBitmap API. By moving both the decompression of compressed image formats and subsequent pixel-level operations into background threads, web applications can eliminate frame drops and maintain responsive user interfaces during heavy image-processing tasks.

The Decoding Mechanism

Browsers do not require the DOM or the standard HTML <img> element to decompress WebP data. Inside a Web Worker, WebP binary data can be fetched via fetch() as an ArrayBuffer or a Blob.

Once the data is retrieved, the createImageBitmap() global function decodes the WebP format asynchronously:

const response = await fetch('image.webp');
const blob = await response.blob();
const imageBitmap = await createImageBitmap(blob);

Because createImageBitmap runs entirely within the worker context, decoding the WebP image does not block the main execution thread.

Manipulating Pixels with OffscreenCanvas

Once decoded into an ImageBitmap, the data can be rendered and altered using an OffscreenCanvas. This object can either be instantiated directly inside the worker via new OffscreenCanvas(width, height) or transferred from the main thread using canvas.transferControlToOffscreen().

Inside the worker, a rendering context (2d or webgl) is extracted from the OffscreenCanvas:

  1. Rendering: Draw the decoded ImageBitmap using ctx.drawImage(imageBitmap, 0, 0).
  2. Accessing Pixels: Extract raw RGBA pixel arrays with ctx.getImageData(0, 0, width, height).
  3. Manipulation: Directly modify the Uint8ClampedArray to apply filters, transformations, edge detection, or custom algorithms.
  4. Updating: Write the manipulated pixels back onto the canvas with ctx.putImageData().

Exporting and Displaying Results

After manipulation is complete, the worker can output the data without involving the main thread in rendering overhead:

  • Transfer to Main Canvas: Call canvas.transferToImageBitmap() to generate a lightweight bitmap that can be posted back to the main thread via postMessage() and rendered instantly.
  • Re-encoding: Use canvas.convertToBlob({ type: 'image/webp' }) to compress the manipulated image data back into a WebP file directly within the worker, making it ready for storage or network upload.

This architecture ensures that network fetching, WebP decoding, graphical transformations, and re-encoding occur completely off the main thread.
