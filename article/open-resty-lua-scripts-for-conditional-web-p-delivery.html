OpenResty Lua Scripts for Conditional WebP Delivery

Serving WebP images conditionally allows modern clients to receive smaller, highly compressed files while maintaining backwards compatibility for older browsers. OpenResty leverages the lua-nginx-module to inspect incoming HTTP request headers—such as the User-Agent and Accept headers—and dynamically rewrite image URLs to point to .webp versions when supported, falling back seamlessly to JPEG or PNG assets when WebP is unavailable.

Detecting Support via Headers

While standard WebP detection typically targets the Accept: image/webp header, certain applications, webviews, and legacy browsers require matching against known User-Agent strings. OpenResty exposes these headers natively through the ngx.var and ngx.req APIs.

To implement User-Agent-based matching alongside Accept headers, you extract the relevant headers directly inside an OpenResty Lua block:

local user_agent = ngx.var.http_user_agent or ""
local accept = ngx.var.http_accept or ""

local function supports_webp(ua, acc)
    -- Check Accept header first
    if string.find(acc, "image/webp", 1, true) then
        return true
    end

    -- User-Agent pattern matching for environments omitting Accept
    if string.find(ua, "Chrome/%d+") or 
       string.find(ua, "CriOS/%d+") or 
       string.find(ua, "Firefox/%d+") or 
       string.find(ua, "Version/%d+.*Safari") then
        return true
    end

    return false
end

Complete OpenResty Configuration

The most efficient approach uses rewrite_by_lua_block inside an image-matching location block. This allows OpenResty to verify that the client supports WebP and that a corresponding .webp file exists on the local file system before mutating the request URI.

server {
    listen 80;
    server_name example.com;
    root /var/www/html;

    location ~* ^(/images/.+)\.(jpe?g|png)$ {
        set $original_path $1;
        set $extension $2;

        rewrite_by_lua_block {
            local ua = ngx.var.http_user_agent or ""
            local acc = ngx.var.http_accept or ""

            -- Evaluate User-Agent and Accept patterns
            local is_webp_capable = string.find(acc, "image/webp", 1, true) or
                                   string.find(ua, "Chrome/[%d%.]+") or
                                   string.find(ua, "Firefox/[%d%.]+") or
                                   string.find(ua, "Android")

            if is_webp_capable then
                local webp_path = ngx.var.document_root .. ngx.var.original_path .. ".webp"
                local file = io.open(webp_path, "r")

                if file then
                    file:close()
                    -- Mutate the internal URI to the WebP equivalent
                    ngx.req.set_uri(ngx.var.original_path .. ".webp")
                end
            end
        }

        # Set caching headers and handle fallbacks
        add_header Vary "Accept, User-Agent";
        try_files $uri =404;
    }
}

Script Execution Flow

  1. Capture Image URIs: The Nginx location directive intercepts incoming requests for .jpg, .jpeg, and .png assets within the specified directory.
  2. Evaluate Capability: The rewrite_by_lua_block evaluates the client's Accept and User-Agent strings. If a client like Google Chrome or Android WebKit matches, the script flags the request as capable.
  3. Verify File Existence: Using Lua's standard I/O library (io.open), the script checks the local disk to confirm that a pre-converted .webp file exists alongside the original image.
  4. Internal Rewrite: If the file exists, ngx.req.set_uri() reroutes the request to serve the .webp asset. If the file is missing or the client is unsupported, the rewrite is bypassed.
  5. Cache Control: The add_header Vary "Accept, User-Agent" instruction informs edge caches, CDNs, and reverse proxies that the served asset depends directly on the client's request signatures.
