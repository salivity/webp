Animated WebP Looping: Infinite and Custom Counts

Animated WebP images fully support both infinite looping and restricted iteration counts. By utilizing dedicated metadata within the file's container format, creators can specify whether an animation repeats endlessly or halts after a predetermined number of cycles. This article covers how the loop count mechanism works in the WebP specification, how browsers interpret these values, and how you can configure animation cycles during encoding.

The Technical Mechanism: The ANIM Chunk

Animated WebP files are structured using the RIFF (Resource Interchange File Format) container. Within this format, global animation parameters are stored inside an ANIM chunk.

Inside the ANIM chunk, a specific 16-bit field is reserved for the "Loop Count." Because it is a 16-bit unsigned integer, it can accept values ranging from 0 to 65,535:

  • Value of 0 (Infinite Loop): In the WebP specification, setting the loop count to 0 instructs the decoder to repeat the animation continuously without stopping.
  • Value of 1 to 65,535 (Finite Iterations): Setting the loop count to any non-zero value dictates the exact number of times the sequence will play. For example, a value of 1 means the animation plays once from start to finish and halts. A value of 3 means it will play through three complete cycles before stopping.

When a finite animation completes its final iteration, standard decoders remain paused on the last frame of the sequence.

Browser and Decoder Compatibility

Modern web browsers—including Google Chrome, Mozilla Firefox, Apple Safari, and Microsoft Edge—fully implement the WebP container specification. As a result, they accurately respect both infinite and finite loop limits.

This behavior contrasts with older animated formats like standard GIF, which occasionally suffered from inconsistent decoder behavior across different platforms regarding whether 0 or 1 signified an infinite loop. WebP's strict specification ensures consistent cross-platform behavior.

Configuring Loop Counts

You can set loop limits using official WebP command-line utilities or graphical image editing software.

When using Google's img2webp utility, the -loop parameter is used to define the count:

  • To loop infinitely: img2webp -loop 0 frame1.png frame2.png -o animation.webp
  • To loop exactly twice: img2webp -loop 2 frame1.png frame2.png -o animation.webp

Most visual editors and export plugins, such as GIMP, Photoshop (via the WebPShop plugin), or FFmpeg, expose this setting via an "Animation" or "Loop Count" export dialogue. Selecting an option like "Loop Continuously" writes a 0 to the header, while leaving it unselected or entering a custom number sets a finite limit.
