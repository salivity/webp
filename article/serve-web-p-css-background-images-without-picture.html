Serve WebP CSS Background Images Without Picture

Serving modern image formats like WebP as CSS background images requires different techniques than standard HTML inline images, as the native <picture> element is unavailable in stylesheets. This article explores the primary methods developers use to conditionally deliver WebP backgrounds with fallbacks to traditional formats like JPEG or PNG: the modern CSS image-set() function, JavaScript-based feature detection classes, and HTTP content negotiation.

The Modern Approach: CSS image-set()

The standard, modern method for conditional background image serving in pure CSS is the image-set() functional notation. Similar to the srcset attribute in HTML, image-set() allows developers to provide a list of image candidates along with format and resolution hints, letting the browser download only the format it supports.

.hero {
  background-image: url("background.jpg"); /* Fallback for legacy browsers */
  background-image: -webkit-image-set(
    url("background.webp") type("image/webp"),
    url("background.jpg") type("image/jpeg")
  );
  background-image: image-set(
    url("background.webp") type("image/webp"),
    url("background.jpg") type("image/jpeg")
  );
}

When a browser encounters this property, it evaluates the type() attribute. If it supports image/webp, it downloads the WebP asset and ignores the fallback. Older browsers that do not support image-set() simply use the standard url() declared immediately before it.

Class-Based Detection with JavaScript

Before image-set() gained widespread cross-browser support, the industry standard was client-side feature detection using Modernizr or a tiny inline JavaScript snippet.

This approach tests whether the browser can decode a tiny base64-encoded WebP image. Upon validation, the script appends a .webp or .no-webp class to the document's <html> element.

// Quick inline detection script
const webp = new Image();
webp.onload = webp.onerror = function () {
  if (webp.height === 2) {
    document.documentElement.classList.add("webp");
  } else {
    document.documentElement.classList.add("no-webp");
  }
};
webp.src = "data:image/webp;base64,UklGRjoAAABXRUJQVlA4IC4AAACyAgCdASoCAAIALmk0mk0iIiIiIgBoSygABc6WWgAA/veff/0PP8bA//LwYAAA";

CSS rules then target these classes specifically:

.card {
  background-image: url("card-bg.jpg");
}

.webp .card {
  background-image: url("card-bg.webp");
}

Because the script runs in the <head> before the DOM renders, the browser only initiates a download for the appropriate image file, preventing double-fetching.

Server-Side Content Negotiation

Another seamless method eliminates CSS modifications entirely by handling conditional delivery on the web server.

Browsers that support WebP send an explicit HTTP request header:

Accept: image/webp,image/apng,image/*,*/*;q=0.8

Web servers (such as NGINX or Apache) or Content Delivery Networks (CDNs) can be configured to check for the presence of image/webp in the Accept header. If present, the server serves the WebP variant of the file while maintaining the original URL (e.g., background.jpg) and responding with a Vary: Accept header to ensure proper caching.

/* The CSS requires no format logic */
.banner {
  background-image: url("banner.jpg");
}

Summary

For modern web applications, the native CSS image-set() function is the standard solution for format selection without HTML wrappers. For projects requiring broader legacy support or streamlined stylesheets, class-based detection scripts and server-level content negotiation remain robust alternatives.
