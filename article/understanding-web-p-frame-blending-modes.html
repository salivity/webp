Understanding WebP Frame Blending Modes

Animated WebP files rely on specific frame blending modes within each animation frame chunk to dictate whether new pixels merge with existing canvas content or completely overwrite it. This mechanism enables efficient delta encoding by allowing decoders to update only modified portions of an image, balancing visual fidelity with compact file sizes. Understanding how these modes operate is essential for preventing visual artifacts such as ghosting or unwanted transparency in animated media.

The Role of the WebP ANMF Chunk

In the WebP container specification, animated files store each individual frame inside an ANMF (Animation Frame) chunk. This chunk defines the frame's position coordinates (X and Y offsets), dimensions (width and height), frame duration, disposal method, and the 1-bit blending method flag.

The blending method flag directly instructs the decoder on how to composite the incoming frame onto the existing canvas.

Blending Modes: Combine vs. Overwrite

The blending method flag provides two states: Blend and Do Not Blend.

1. Blend Mode (Combine Pixels)

When the blending flag is set to 0 (Blend), the rendering engine performs standard alpha compositing (typically the "over" operator).

  • How it works: The decoder calculates the final pixel color by combining the color and alpha channels of the new frame with the color and alpha channels already present on the canvas within that frame's bounding rectangle.
  • Result: Fully opaque pixels completely cover previous pixels, while semi-transparent or fully transparent pixels allow the underlying pixels from the previous frame to show through.
  • Use Case: This mode is ideal for animating moving elements across static backgrounds or rendering smooth, translucent effects like smoke, shadows, and anti-aliased edges without clearing the canvas.

2. Do Not Blend Mode (Overwrite Pixels)

When the blending flag is set to 1 (Do Not Blend), the decoder disables alpha compositing.

  • How it works: The raw pixel data of the new frame directly overwrites the canvas area defined by the frame's bounding box. The color and alpha channels are copied directly into the canvas buffer.
  • Result: If a pixel in the new frame has an alpha value of zero (fully transparent), the corresponding canvas pixel becomes fully transparent. It does not display the pixel from the previous frame; instead, the underlying content is erased.
  • Use Case: This mode is essential when replacing complete regions of the canvas, especially when an object moves and leaves an empty or transparent space behind that should reveal the webpage background rather than retained frame data.

Interaction with the Disposal Method

Frame blending works in tandem with the frame disposal method (dispose_method). Before a new frame's blending mode is applied, the disposal flag dictates what happens to the canvas:

  • Do Not Dispose: The canvas retains the current frame's output. The subsequent frame's blending mode will combine with or overwrite this retained image.
  • Dispose to Background: The canvas area covered by the current frame is cleared to fully transparent black before the next frame is rendered. In this scenario, setting the next frame to "Blend" or "Do Not Blend" yields the same visual result because there are no existing pixels to blend with.

By pairing precise bounding boxes with the correct combination of blending and disposal flags, WebP encoders selectively alter only the pixels that change between frames, drastically reducing file size compared to full-frame image updates.
